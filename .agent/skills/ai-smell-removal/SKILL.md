# AI臭除去スキル (Anti-AI-Smell)

文章を公開・提出する前の最終仕上げとして、AI特有の文体パターンを除去する。
既存の `note-gen` ワークフロー内の「AI臭さの完全排除」節と `04_hallucination_prevention.md` を補完する汎用版。

## 手順

1. **診断**: 下のパターン一覧でスキャンし、該当箇所を洗い出す。
2. **書き換え**: 意味と事実を変えずに直す。具体情報の捏造は絶対にしない。具体化に必要な情報が素材に無ければ、勝手に作らず、削るか「要確認」として残す。
3. **声の調整**: ユーザーの文体サンプル（過去のnote記事・X投稿）があれば、文の長さのばらつき、語尾、温度感をそれに寄せる。
4. **再スキャンと自己採点**: 書き換え後に再チェックし、AI臭スコア（0〜100、低いほど人間らしい）の目安を出す。36以上ならもう一段直す。
5. **出力**: 修正版と、修正箇所の一覧（何を・なぜ直したか）をセットで提示する。

## 日本語のAI臭パターンと直し方

### 1. 曖昧な断定
- 例：「〜かもしれません」「〜と言えるでしょう」「〜と考えられます」「〜ではないでしょうか」
- 直し方：根拠があるなら「です・ます」で断定する。根拠が無いなら、その文自体を削るか、条件を具体的に書く。

### 2. 抽象語の多用
- 例：「様々な」「多くの」「効果的な」「革新的な」「重要な役割を果たす」
- 直し方：具体名・数字・場面に置き換える（「様々なツール」→「Claude CodeとAntigravity」）。素材に具体情報が無ければ捏造せず、削るか要確認にする。

### 3. 締めの定型句
- 例：「いかがでしたでしょうか」「参考になれば幸いです」「最後までお読みいただきありがとうございます」
- 直し方：丸ごと削除する。締めが必要なら、具体的な次の一手か、読者への問いかけで終える。

### 4. 接続詞の過多
- 例：「以上のことから」「したがって」「つまり」「また、〜も重要です」の連発
- 直し方：多くを削り、文と文を直接つなぐ。本当に論理の橋が要る場所だけ残す。

### 5. 文の長さが均一・長文すぎる
- 一文50文字超は分割を検討する。短い文と長い文を混ぜてリズムを作る。全ての文が同じ長さ・同じ語尾（です・です・です）なのは典型的なAI臭。「〜しましょう」「〜することが重要です」などの語尾の3連続も排除する（note-gen節と共通）。

### 6. 意義の水増し・大げさな言い回し
- 例：「〜の新時代」「革命的な」「大きな一歩」「注目されています」
- 直し方：事実だけを書く。評価は具体的な数字や出来事に語らせる。「王」「〜の舞」「〜の調べ」「君」などのポエミーな比喩も禁止（note-gen節と共通）。

### 7. 型にはまった構成と並列
- 三点セットの並列、「〜だけでなく〜も」の多用、見出し＋箇条書きの過剰な整形、太字の乱用。
- 直し方：並列は実態に合わせて数を変える。地の文で書ける部分は地の文に戻す。

### 8. 導入の一般論
- 例：「近年、〜が注目されています」「現代社会において〜」
- 直し方：一般論から入らず、具体的な場面・体験・数字から書き始める。

### 9. 実戦的な言葉遣い（LoL文脈）
- LoL記事では、実戦的なプレイヤー目線の言葉（「即死ライン」「ウェーブフリーズ」「ワンコン」等）を使い、教科書的な説明口調を避ける。

## 英語のAI臭パターン（英語文の場合）
- Significance inflation、"delve" "landscape" "furthermore" "moreover" 等の常套語の多用、em dash（—）の多用、rule of three、"not only... but also" の連発、"It's important to note" "In conclusion" の定型つなぎ。
- 原則は日本語と同じ：具体化、断定、定型句の削除、文長のばらつき。

## 禁止事項
- 体験談・数字・固有名詞を捏造して具体化しない。
- 意味や事実関係を変えない。直すのは文体だけ。
- 構造化データ、コード、仕様文書、表が主体の実務文書には適用しない（対象は読み物・発信文）。

## 出力フォーマット

```

（書き換えた文章）


- 「〜かもしれません」→ 断定に変更（パターン1）
…

AI臭スコア目安：修正前 約○○ → 修正後 約○○
```
