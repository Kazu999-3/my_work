# note収益化パイプライン

## 用途

ツール・サービス紹介系の note 記事（アフィリエイトリンクを含むもの）を、品質チェックを挟みながら4工程で作成する手順。

- **使う場面**：新しいツール・サービスの紹介記事、解説記事、アフィリエイト記事を note に出すとき
- **使わない場面**：LoL戦術記事には使わない。そちらは既存の forge プロトコル／note-gen の担当

## 全体フローと工程間の受け渡し

```
工程1 初稿生成 ──初稿──▶ 工程2 辛口査定 ──改善点3点──▶ 工程3 リライト ──決定稿──▶ 工程4 X宣伝スレッド
```

- 工程1の出力（初稿）が工程2の入力になる
- 工程2の出力（改善点3点）と初稿が工程3の入力になる
- 工程3の出力（決定稿）のタイトルと要約が工程4の入力になる
- 各工程の成果物は省略せず全文を次工程へ渡す
- 工程の途中でユーザーの確認を挟んでよい。特に工程3の決定稿は、工程4へ進む前にユーザーの確認を得る

## 工程1：初稿生成

### 目的

構造化された知識（ファクト）をもとに、note 記事の初稿を作る。

### 入力

- 対象ツール・サービス名
- ツールの詳細ファクト（機能、手順、料金、対象ユーザーなど、出典のある構造化知識）
- アフィリエイトリンク（ある場合）

### 実行時の指示

- プロのIT・ツールライターとして、個人の業務効率化を支援する立場で書く
- 読者が今すぐ試したくなる、具体的で実用的な活用手順を提示する。手順は入力されたファクトの steps に準拠し、ファクトにない手順を創作しない
- アフィリエイトリンクがある場合、記事の途中の適切な箇所と記事の最後のまとめ部分の合計2箇所以上に、自然なハイパーリンク形式で挿入する（例：「[ツール名の公式サイトはこちら（無料登録可能）](リンクURL)」）
- 語尾は「〜です」「〜ます」の親しみやすく人間味のあるトーンで書く
- 「王」「王国の舞」などのポエミーな比喩表現は一切使わない
- Markdown形式で出力し、タイトルは32文字以内で最上部に「# タイトル」として記述する

## 工程2：辛口査定

### 目的

初稿を厳しい読者の目で査定し、リライトで直すべき点を絞り込む。

### 入力

- 工程1の初稿（全文）

### 実行時の指示

- IT・ツール系記事を日々読んでいる、非常に目が肥えた「辛口な一般読者」になりきって読む
- 読者の視点から「物足りない点」「分かりにくい点」「AIっぽくて説得力に欠ける点」「アフィリエイトへの誘導が強引な点」などを厳しく客観的に指摘する
- **良かった点（褒め言葉）は一切書かない**
- **改善すべきポイントのみを、ちょうど3点、箇条書きで具体的に指摘する**
- 指摘は簡潔かつ手短に書く

## 工程3：リライト（決定稿）

### 目的

辛口査定の指摘をすべて解消し、公開できる決定稿に仕上げる。

### 入力

- 対象ツール・サービス名
- 工程1の初稿（全文）
- 工程2の指摘事項（3点）
- アフィリエイトリンク（ある場合）

### 実行時の指示

- プロのIT・ツールライターとして、品質管理部（辛口読者）からの指摘が届いたという前提でリライトする
- 指摘された問題点を完全に修正し、説明の具体性を高める。指摘への対応を省略しない
- 「王」「王国」「舞」などのポエミーなAI臭い表現は絶対に排除し、一般の人間が書いたブログ記事と見分けがつかないナチュラルな文章にする
- アフィリエイトリンクがある場合、記事中と最後の計2箇所以上に自然なハイパーリンク形式で必ず挿入する
- Markdown形式で出力し、タイトルは32文字以内で最上部に「# タイトル」として記述する
- 文体の最終仕上げ（AI臭除去）が必要な場合は、別スキル ai-smell-removal の担当とする。この工程では内容と説得力の改善に集中する

## 工程4：X宣伝スレッド

### 目的

決定稿を X で宣伝する3連投スレッドを作る。

### 入力

- 決定稿の記事タイトル
- 決定稿の要約
- note記事のURL（公開後に確定する場合は、公開後にこの工程を行う）

### 実行時の指示

- プロのIT・ツールライターであり、SNSを活用したマーケターとして書く
- スレッドは正確に3つの投稿で構成する
- 各投稿は、ツールを使うことで解決できる課題やメリットを明確にし、続きが読みたくなるフックを持たせる
- 3つ目（最後）の投稿の末尾に「続きはこちらから👇」と note 記事のURLを必ず掲載する
- 各投稿のテキストは日本語140文字以内におさめる
- AI臭い大げさな表現は避ける
- 出力形式：プログラム連携用のJSONではなく、**3つの投稿文をそのままコピーして投稿できる形で提示する**

## 共通の注意

- **捏造禁止**：数値・実績・体験談・利用者の声などを創作しない。入力されたファクトとユーザーが提供した情報の範囲で書く
- **事実と推測を分ける**：ファクトにないことは推測として明示するか、書かない
- **公開・投稿は必ずユーザーの承認後**：note への公開、X への投稿は、このスキルでは実行しない。成果物を提示し、ユーザーの承認を得てから別途行う
- アフィリエイトリンクのURLはユーザーが提供したものをそのまま使う。リンク先やURLを推測で作らない
