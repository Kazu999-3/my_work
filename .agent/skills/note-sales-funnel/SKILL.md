# note 販売ファネル（発信→信頼→購入の型）

有料記事（note / Brain）を売るための、発信・記事・価格・診断の型の集まり。出典は実際に読んで取り入れた X ポストの型（テンペ @HimazinProducer、くろねこ @kuro_affi、とら @3Imzdo3）。他者の収益数字は未検証の主張として扱い、実績として書かない・約束しない。

## チャネルの役割分担（とら）

- **X ＝ 認知**：知ってもらう場所。売り込みの場にしない
- **note ＝ 信頼づくり**：読んで「この人の判断は使える」と思ってもらう場所
- **Brain ＝ 購入**：買う場所。レビューと紹介が効く

各チャネルで役割を混ぜない。X で直接売ろうとせず、note で信頼を作り、購入は Brain（または note 有料記事）へ寄せる。

## 発信の型（テンペ）

- 発信は「長文ポスト ＋ 短い動画 ＋ 同じ記事への誘導」を、**角度を変えて何度も繰り返す**。1 回出して終わりにしない
- 締めの型：**「後で見返せるように保存がおすすめ」**（保存される投稿は伸びる）
- 販売ページ（LP）には、デモ動画・無料サンプル・ROI シミュレーターのような「買う前に中身と効果を確かめられるもの」を置く

## Xポストの4層構造（500円note誘導フレームワーク）

出典：リポジトリの `02_FACTORY/PROMO/THREADS/x_viral_lead_framework.md`（2026-11-25 統合）。500円noteのような低価格商品へ X ポスト単体で誘導するための、1投稿の中身の型。上の「発信の型（テンペ）」が発信全体の型、こちらは投稿レベルの型。

誘導の流れ：**X無料ポスト → ブックマーク＆RT（拡散・信頼）→ note無料部分（実戦データ・目次のチラ見せ）→ 低価格note購入 → 一部の購入者へバックエンド（個別添削などの高価格商品）**。チャネル役割分担に「保存・RT」と「購入後のバックエンド」の段を足した形になる。

1投稿は次の4層で組む：

1. **Hook（違和感・常識の破壊）**：1行目でスクロールを止める。多くのプレイヤーが信じている「間違った常識」や、言語化できていないモヤモヤを突く。「〇〇解説します！」のような告知型の書き出しは使わない
2. **Data（客観的事実・実測の数字）**：感想・精神論を排し、動画解析やタイムラインから得た具体的な数字（〇分〇〇秒、スキル名、アイテム名）を出す
3. **Reason（なぜ勝てるかの構造）**：その行動が必要な理由を言語化し、「なるほど」と納得させる
4. **Exit（思考の呼び水＋note誘導）**：実戦のシチュエーション判断を問いかけ、詳細（対面別リスト、逆算タイムテーブル等）はリプ欄の note へ流す。価格は「缶コーヒー2本分」のように日常の支出へ換算して見せると心理的ハードルが下がる

テンプレートは3型ある（コピペ用の全文は出典ファイルに収載）：

- **対面マッチアップ・キルゾーン特化型**：見落としの指摘 → 通説を否定し実戦データの手順を提示 → 初手間合い・キルゾーン発生時刻・パワースパイクを箇条書き → 対面別の判断表は note へ
- **JGルート・定石タイマー特化型**：理不尽に責められる側への共感 → 現パッチの最短到達時刻 → 警戒すべき3つの時刻を箇条書き → 逆算タイムテーブル完全版は note へ
- **ランク脱出・思考トリガー型**：「神プレイではなく、やってはいけないミスを3つ削る」という型の提示 → ミスの列挙 → シチュエーション判断の問いかけ → 判断の正解基準は note へ

投稿前チェック（出典のチェックリストより）：

- AI特有の社交辞令・淡白な締め（「いかがでしたでしょうか」等）が入っていないか（仕上げは ai-smell-removal でも確認する）
- 「必ず勝てる」などの誇大な約束になっていないか。効果の数字は、自分の実測に基づく場合だけ書く
- 具体的な数字が最低2つ入っているか
- リプ欄の note リンクに「何が手に入るか」が明記されているか

## 記事の型（くろねこ＋とら）

- **テーマ選定が 9 割**（くろねこ）。書く前に「誰の・どの悩みか」を決める。ターゲットは「特定の仕事の人の具体的な悩み」まで絞る（とら）
- **実績のある型に流し込む**（くろねこ）。ゼロから型を発明せず、売れている構成に自分の題材を入れる
- 選べる記事の構成（とら）：**悩み → 判断基準 → 比較 → 向いている人 → 注意点 → 選ぶ手順**。「売る記事」にしない。読者が自分で選べる材料を出す記事にする
- 役割分担（とら）：**AI は仮説と整理、人間は公式情報で事実確認**。数字・仕様・価格は公式情報で裏を取ってから書く

## 価格と導線の型

- **低価格の入口商品 → 高価格への導線**（くろねこ）。いきなり高価格を売らない
- **段階値上げ**（テンペ）：先行価格 → 段階的に上げる → 定価、の階段を作り、早い購入に理由を持たせる。あわせて「総額◯円相当のパッケージ」化で単品の寄せ集めに見せない
- 確定済みの設計例（Brain 第1弾）：**先行 1,480 円 → 2,980 円 → 定価 4,980 円**、紹介報酬 30%。新しい商品を設計するときはこの階段を基準に置く

## 数字の切り分け（とら）

売れ行きが悪いときは一括りにせず、止まった段ごとに診断して打ち手を変える。

| 止まった段 | 症状 | 打ち手の方向 |
| --- | --- | --- |
| 読まれない | 投稿・記事に到達していない | 発信の角度と回数（テンペ型の繰り返し）、テーマ選定の見直し |
| 進まない | 読まれるが最後まで進まない・離脱する | 記事構成（悩み→判断基準…の流れ）、冒頭の引き |
| 押されない | 読まれるが購入ボタンまで行かない | 無料サンプル・デモなど「中身を確かめる材料」、価格の階段 |
| 成果なし | 買われるが読者の成果につながらない | 中身の具体性、選ぶ手順・注意点の不足を補う |

## 小さく始める（とら）

- **1 ターゲット・1 商品・1 記事**から検証する。同時に複数を広げない
- 検証で数字の止まり段が分かったら、その段だけ直して再検証する

## 手順（販売計画を立てるとき）

1. ターゲットを「特定の仕事の人の具体的な悩み」まで 1 つに絞る
2. 入口商品（低価格）と、その先の高価格・定価までの階段を決める
3. 記事を「悩み→判断基準→比較→向いている人→注意点→選ぶ手順」で構成する。事実は公式情報で確認する
4. 発信計画を作る：長文ポスト＋短尺動画＋誘導を、角度を変えて複数回。締めは「保存がおすすめ」
5. 販売ページに無料サンプル等の「確かめる材料」を置く
6. 公開後は数字を4段（読まれない／進まない／押されない／成果なし）で切り分けて診断する
