# ユーザビリティ憲章 (Usability & UX Rules)

本ファイルは、AIエージェントがフロントエンド（Web UI）やアルゴリズムを実装する際に、**ユーザーの明確な指示がなくても自律的に組み込むべき「使いやすさの絶対基準」**を定めたものです。
AIはUI設計や機能実装を行う際、常にこの憲章を暗黙の要件として適用しなければなりません。

## 1. 一覧表示における絶対要件
データの一覧（例：チャンピオン辞典、マッチアップリスト、攻略ライブラリなど）を画面に表示する際は、必ず以下の機能を組み込むこと。
- **ソート機能 (Sort)**: デフォルトで「更新日（最新順）」でソート可能にすること。その他、名前順や評価順での切り替え機能を実装する。
- **絞り込み・検索 (Filter/Search)**: 大量のデータから目的のものを瞬時に見つけられるよう、カテゴリ（ロール・役割）での絞り込みや、フリーワード（チャンピオン名など）での検索フィルターを実装する。

## 2. マッチング・バランシングの絶対要件
プレイヤーのチーム分けやリソースの分配など、バランシングに関わるアルゴリズムを実装する際は、以下の要件を満たすこと。
- **均等化 (Equalization)**: プレイヤーの能力値（MMR等）のチーム合計が可能な限り均等になるよう、数学的な最適化ロジックを必ず含めること。
- **役割の尊重 (Role Preference)**: ユーザーが「やりたくない（NG）」と設定した役割やポジションには、絶対にアサインされないような強い制約（ハード制約）を設けること。

## 3. エラーとフィードバックの視認性
- **ローディングと結果**: 「画面が真っ暗になる」「ボタンを押しても反応がない」という状況を避けるため、データ取得中は必ずローディングインジケーター（スピナー等）を表示し、エラー時は人間が読んで理解できる日本語のメッセージ（トースト等）を表示すること。
- **通知カラーの厳守**: 成功メッセージはエメラルドグリーン（`bg-emerald-950/30 text-emerald-400 border-emerald-800/60`）を使用し、琥珀色（警告色）と混同させないこと。

## 4. 確定デザインシステム ＆ カラーパレット規約 (モダンライトUI)
- **全体背景**: 清潔感と視認性に優れたモダン・スレートオフホワイト（`#f8fafc`、Tailwind `bg-stone-50 dark:bg-stone-950`）。旧砂色（`#eae4d4`）は完全廃止。
- **カード・サーフェス**: 清潔なモダン白カード（`bg-white dark:bg-stone-900 border border-stone-200/90 dark:border-stone-800 shadow-xs`）。ダーク接頭辞なしの黒ベタ塗り（`bg-stone-900`）は禁止。
- **文字コントラスト**: 本文は `text-stone-700 dark:text-stone-300`、見出しは `text-stone-900 dark:text-white font-bold`。白背景で薄いグレー文字（`text-stone-400`）を使わないこと。
- **アクセント**: Hextechアンバーゴールド（Tailwind `amber-500` / `amber-400`、選択時ハイライト: `bg-amber-500/10 border-amber-500 text-amber-950 font-black`）。

## 5. ポータル標準UIトークン ＆ スッキリ化規約
- **2層タブ集約（スマホ最適化）**:
  - タブ項目が4つ以上ある場合、1行に無理に並べず「大グループ（例: ランキング/名簿/分析）」と「サブ切替」の2層に集約すること。スマホでの改行崩れや認知負荷を防止する。
- **ファーストビュー最優先**:
  - 画面最上部に縦長の巨大ヒーローや黒グラデーションバナーを置くことを禁止する。
  - 統計サマリーやタグ一覧は `<details>` アコーディオンで折りたたみ可能にし、検索窓・主要コンテンツを画面ファーストビューに配置すること。
- **二重ヘッダーの撤廃**:
  - ページ側（`page.tsx`）で見出しを持ち、埋め込まれるコンポーネント（`*TabContent.tsx`）側でも見出しを持つ二重ヘッダーを禁止する。画面タイトルは親側の1箇所に一本化する。
