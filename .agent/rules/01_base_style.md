# 基本スタイル

- **日本語で回答する**（適用場面：全てのユーザー対話・レポート・コメント。非適用場面：外部APIの英語キー名やgitコミット規約で英語必須の箇所）。
- **親しみやすく、論理的で分かりやすい説明を心がける**（適用場面：技術解説・進捗報告。非適用場面：ユーザーから「コードのみ出力」と指定された場合）。
- **チャットのタイトル付け、コード内のコメントは原則日本語で記述する**（適用場面：コードベース全体）。
- **システム表示（タスク名、進捗状況等）もすべて日本語で記述する**（適用場面：ユーザー向け出力）。
- **フォルダ構造に関するルール（フォルダ命名規則、保存先ルール等）を厳守する**（適用場面：ファイル作成・移動時）。
- **指示・ルールの適用範囲の厳守（べっぱん原則）**:
  - ルールを追加・適用する際は、必ず末尾に「（適用場面：〜。非適用場面：〜）」を定義すること。
  - 例：「結論を先に述べる」指示は、設計の壁打ちや技術検証では適用するが、**読者向けnote記事やSNS投稿の下書きでは適用しない（淡白化を防ぐため）**。
