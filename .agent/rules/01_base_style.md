# 基本スタイル

- **日本語で回答する**（適用場面：全てのユーザー対話・レポート・コメント。非適用場面：外部APIの英語キー名やgitコミット規約で英語必須の箇所）。
- **親しみやすく、論理的で分かりやすい説明を心がける**（適用場面：技術解説・進捗報告。非適用場面：ユーザーから「コードのみ出力」と指定された場合）。
- **チャットのタイトル付け、コード内のコメントは原則日本語で記述する**（適用場面：コードベース全体）。
- **システム表示（タスク名、進捗状況等）もすべて日本語で記述する**（適用場面：ユーザー向け出力）。
- **フォルダ構造に関するルール（フォルダ命名規則、保存先ルール等）を厳守する**（適用場面：ファイル作成・移動時）。
- **指示・ルールの適用範囲の厳守（べっぱん原則）**:
  - ルールを追加・適用する際は、必ず末尾に「（適用場面：〜。非適用場面：〜）」を定義すること。
  - 例：「結論を先に述べる」指示は、設計の壁打ちや技術検証では適用するが、**読者向けnote記事やSNS投稿の下書きでは適用しない（淡白化を防ぐため）**。
- **イミュータブル・プロパティ規約（フロントマター標準 / Blooming・りゅう・ジョージぱぱ原則）**:
  - `01_INTEL/` や `02_FACTORY/` で新規作成・管理するすべてのMarkdownノートには、冒頭に以下の統一YAMLメタデータを付与すること。
  - 特に**公開日（`published_at`）、取込日（`captured_at`）、そして内容確認日（`verified_at`）を厳密に分離**し、日時をLLMに推測させないこと。単なる誤字修正等のファイル更新日と「実戦・実測で中身を確認した日」を混同してはならない。
  ```yaml
  ---
  title: "ノートの正式名称"
  status: verified # verified（実戦確定）| experimenting（検証中）| deprecated（旧仕様）
  source_type: official # official（公式SSoT）| empirical（実戦実測）| ai_derived（AI派生）
  published_at: 2026-XX-XX # 一次情報の公開日（不明なら unknown）
  captured_at: 2026-XX-XX  # 保存・取込日時
  verified_at: 2026-XX-XX  # 内容確認日・実戦実測検証日（未確認なら unverified）
  tags: [LoL, Tactics, TOP]
  ---
  ```
- **検索汚染防止 ＆ アーカイブ分離原則（ジョージぱぱ原則）**:
  - `status: deprecated`（旧パッチ・旧仕様・終了した設計）のノートは、削除せず履歴として残すが、タイトル先頭に必ず **`[旧]`** を付与すること（例：`[旧] パッチ26.1 TOPダリウス戦術.md`）。
  - 現役の戦術バイブルや検索結果に旧情報が混ざって誤用される事故を構造的に防ぐこと（適用場面：全てのナレッジ・戦術ファイル・索引）。
- **原本非破壊 ＆ 出典リンク必須原則（ハシ・Antigravity原則）**:
  - **原本非破壊**: AIが資料やメモを整理する際、元ファイル（一次ソース）を直接上書き・破壊してはならない。必ず別名・派生ノートとして構造化すること。
  - **出典リンクの徹底**: AIが作成・要約する全てのノートには、必ず一次情報源（元WebサイトURL、元動画URL、または元ファイルの相対パス）を冒頭または所定欄に明記すること（ハルシネーション防止とファクトチェック動線の確保）。
