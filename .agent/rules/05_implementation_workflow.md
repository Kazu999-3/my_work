# 実装ワークフロー (Implementation Workflow)

**[基本運用・ワンストップ全自動デプロイ]** 機能実装やコード修正の際は、以下のステップを途中で確認を挟まず全自動・一気通貫で完了させること：

1. 🛠️ **機能実装・コード修正**
2. 🛡️ **既存接続・認証・エンドポイントの非破壊検証 (Regression Protection)**
   - リファクタリングやコード削減時に、既存の API 通信先（`/api/auth/verify` 等の認証、データ取得ルート）、環境変数、Props、および過去に繋がっていた連携先が破壊・変更されていないか `git diff` で厳密に監査する。
   - 推測でエンドポイント名を書き換えることを厳禁とする。
3. 🧪 **回帰テストスイートの実行 (`npm test`) ＆ 数理ロジック実値検算 (Verifier原則)**
   - バランサー、MMR計算、制約ソルバー、オッズ・配当等の全テストがパスすることを確認。
   - **数理・ゼロサム・判定ロジックの必須検証**: バランサー公平化、オッズ、配当、集計等を変更する際は、「全員が同値」「全員が片側に偏っている」「0・空・未設定」などの境界値テストを必ず実行し、実値生ログで合否判定すること。
   - **符号付き差分の相殺防止**: 偏りの合算後にabsを取るのではなく、各項に絶対値（`Math.abs`）が適用されているか検算すること（$(+1 \times 5) + (-1 \times 5) = 0$ のような数学的恒等式バグの再発防止）。
4. 🔍 **型チェック (`npx tsc --noEmit`) ＆ 本番ビルド検証 (`npm run build`)**
5. 🌐 **実機ブラウザ動作確認（ローカル開発環境で実際にクリック・入力・画面遷移を操作して動作確認・スクリーンショットを記録）**
6. 🧪 **否定的なセルフレビュー（自己批判的検証）**
   - 「過去繋がっていたものが途切れていないか」「使いづらさ・エッジケース」を厳しく検証。
   - **サーバー側のゼロトラスト検証**: フロントのUI制御（ボタン無効化や入力制限）を絶対に過信せず、APIルート側で認証・認可・上限クランプ（例: オッズやベット額の切り詰め）が実装されているかを点検する。
7. 📖 **使い方（`/guide`）＆ 更新情報（`src/lib/changelog.ts`・`/changelog`）の最新化同期**
8. 🚀 **Git commit ＆ Git push（Vercel本番自動デプロイ完了まで一気に完了）**
