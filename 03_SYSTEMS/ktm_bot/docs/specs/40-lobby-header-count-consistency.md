# Bot 指示文40：募集カードのロビー見出しとバナーの人数表示を統一する

## 目的
土曜定期カスタムの募集カードで、同じロビーの人数が場所によって違って見える問題を直す。「2戦目から合流（途中参加）」の人が、どちらのロビーにも配属されていないように見える状態をなくす。

## 現状の問題（2026-11-26、ユーザー指摘＋Muse のコード調査で確認）
2026-11-28(土) のカード（11-25 12:00 投稿、DB連動）で、中初級帯ロビーの人数表示が3か所で食い違っている。実データは「第1戦から2名＋2戦目から合流1名（left）」。

| 表示場所 | 表示 | 数え方 |
|---|---|---|
| 上部バナーのロビー行 | 中初級帯 2/10 → あと8名 | 第1戦に出られる人数（フル＋1戦のみ）＝ match1Count |
| 上部バナーの合同行 | 合同1卓まであと6名 | 第1戦ベースの合同カウント |
| ロビー見出し | 中初級帯ロビー (3/10名 → あと7名) | 途中参加を含む全参加者 ＝ eligibleTotal |
| ロビー内の内訳 | 第1戦から（2/10名）／2戦目から合流（1名） | 第1戦ベース＋内訳 |

- コード上の所在：バナーは `src/utils/recruitmentStatus.js` の `buildDayBanner`（`lobbyLine` が `match1Count`／`match1Remaining` を使用）。見出しは `src/ui/embeds.js` の `applyDayCardState`（`high.joined`／`low.joined` ＝ `parseLobbyBreakdown` の `joined: eligible.length`、`remaining` も eligible ベース）。
- 配属や判定の仕組み自体は正しい（途中参加者は参加時点で帯ロビーが記録され、20:00判定でも第2戦メンバーとして数えられる）。**表示だけの問題**。
- 「2戦目から合流」を第1戦の成立カウントに入れないこと自体は設計どおりで、変えない。

## やること
- [ ] 土曜カードのロビー見出し（`applyDayCardState` の土曜分岐）を、バナーと同じ第1戦ベースに統一する。途中参加者（および1戦のみ参加者）がいる場合は、内訳が分かる形で添える。表示例（この例の体裁に寄せること）：
  - 途中参加なし：`🌱 中初級帯ロビー (2/10名 → あと8名)`（従来どおり）
  - 途中参加あり：`🌱 中初級帯ロビー (第1戦 2/10名 → あと8名／2戦目から合流 1名)`
  - 1戦のみ参加者がいる場合も、第1戦カウントに含まれることが伝わる内訳にしてよい（例：`／1戦のみ 1名`）。文言の細部は表示の一貫性が保てる範囲で任せる。
- [ ] 「あと◯名」の数字も見出しとバナーで一致させる（第1戦ベースの `match1Remaining`）。
- [ ] 日曜カードの参加者見出し（`👥 参加者 (◯/◯名)`）も、バナー（第1戦／第2戦の2行表示）と数え方が食い違っていないか確認し、食い違う場合は同じ考え方で内訳を添える。
- [ ] 変更後、途中参加者を含むカードの表示例（変更前後の文面）を DAILY_LOG に残す。
- [ ] ローカルで Bot の構文チェック（既存の dry-run 手順）が通ることを確認してから push する。

## やらないこと
- 20:00開催判定・合同1卓判定・成立条件など、判定ロジックの変更。
- バナー側（第1戦ベース）の数え方の変更。統一先はバナー側とする。
- ロビー内の内訳セクション（第1戦から／2戦目から合流）の表示変更。
- 参加レコード（recruitment_participants）の持ち方の変更。

## 完了条件
- 途中参加者がいる土曜カードで、バナー・ロビー見出し・内訳の3か所の人数が矛盾なく読めること（本番カードの再描画または次回カードで確認）。
- 途中参加者がいないカードの表示が従来と変わらないこと。
- ユーザーの指示・合意があったかのような記述を DAILY_LOG にしないこと（根拠は本指示文）。

## 未決事項（エージェントが勝手に決めない）
- 見出し文言の細部で迷う場合は、現行の体裁に最も近い案を採用し、DAILY_LOG に採用した文面を記録すること（判断自体は委任する）。
