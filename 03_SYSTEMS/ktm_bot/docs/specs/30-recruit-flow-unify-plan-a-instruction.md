# 指示文30: Discord募集の格上サポート3択を廃止し、Portalプロフィール設定へ一本化する（案A）

作成: 2026-11-23（Muse）
対象: 03_SYSTEMS/ktm_bot
経緯: 指示文28・29の洗い出し報告（`03_SYSTEMS/ktm_bot/docs/reports/28-recruit-flow-inventory.md`）を受けて、ユーザーが 2026-11-23 に **案A（Portalプロフィール設定への一本化）** を採用決定した。洗い出しで判明した問題：①「挑戦してみたい」はDBに何も記録されずバランサーに伝わらない、②警告の発動条件（相対MMR差200）が Portal の帯境界（1450）と無関係、③「別レーンをお願い」「招集してほしい」は管理者へのメンションによる手動対応が前提。

## やること
- [ ] 参加ボタン押下時の「格上対面リスク確認（3択エフェメラル）」のフローを廃止する。対象は `src/handlers/buttons/periodicRecruit.js` の higher_risk 分岐まわり（発動判定、3択ボタンの表示、各ボタンの処理）。
- [ ] 3択に紐づく管理者メンション通知（「格上のレーン変更依頼」「同格メンバー招集希望」の個別案内チャットへの送信）を廃止する。
- [ ] 参加ボタンは、参加受付・辞退・参加形態の変更のみを行う形にする（現行のその部分の動作は変えない）。
- [ ] 募集カードや参加まわりの文面に3択フローを案内する記述が残っていれば、Portalの希望設定への案内に書き換える。例：「格上との対面や、上の帯の試合への参加の希望は、Portalのマイページ（希望設定）でいつでも変更できます」
- [ ] バランサー側が Discord 側のデータ（今回廃止するフローが書いていたもの）を参照していないか確認し、結果を報告する（洗い出しでは「挑戦」は何も書いていなかったため、原則として移行作業は不要なはず）。

## やらないこと
- Portal 側（04_PORTAL）の変更、バランサーのロジック変更。
- 募集の時刻・曜日・開催判定、「あと1名」通知など、3択フロー以外の Bot 機能の変更。

## 完了条件
- `npm run dryrun:recruitment` が全ケース PASS すること。
- 既存の手順でデプロイできる状態にし、削除したフロー・文面の一覧と、バランサー側の参照確認の結果を報告すること。

## 未決事項
- なし。想定外の影響（他フローが3択の結果を使っている等）が見つかったら、決めずに報告すること。
