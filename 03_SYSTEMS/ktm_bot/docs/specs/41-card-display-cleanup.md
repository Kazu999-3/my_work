# Bot 指示文41：募集カード表示の整理（数字の集約・ロビーアイコン変更・都度募集のバッジ非表示）

## 目的
定期カスタム募集カードの「ゴチャつき」を解消し、あわせて都度募集カードの参加者バッジ表示をやめる。ユーザー指摘（2026-11-28）に基づく3点セット。

## 1. 土曜カード：人数表示をバナーに集約する
### 現状の問題
同じロビーの人数が1枚のカードに3回出てくる。
- 上部バナー（`src/utils/recruitmentStatus.js` の `buildDayBanner`）：「👑 上位帯ロビー: 7/10名 → 2部屋目まであと3名」
- フィールド見出し（`src/ui/embeds.js` の `applyDayCardState`）：「👑 上位帯ロビー (7/10名 → 2部屋目まであと3名)」とバナーとほぼ同内容の繰り返し。中初級帯は指示文40で内訳を入れたため、さらに長い
- ロビー内の小見出し（`renderLobbyList`）：「第1戦から（2/10名）」で3回目

### やること
- [ ] 人数の表示は**バナーだけ**に集約する。バナーのロビー行は現行の情報量を維持してよい（例：「💎 上位帯 7/10名（あと3名で2卓目）」「🍀 中初級帯 第1戦2名＋2戦目合流1名」）。文言の細部は、数字が1回だけ出る原則を守れる範囲で任せる
- [ ] フィールド見出しは「💎 上位帯ロビー」「🍀 中初級帯ロビー」のようにアイコン＋ロビー名だけにする（人数・残数は入れない）。※指示文40で入れた見出しの内訳表示は、本指示文の集約に置き換える
- [ ] ロビー内の小見出し「第1戦から」「2戦目から合流」から人数表記を外す
- [ ] 判定ロジック・成立条件・合同1卓の数え方は一切変えない（表示だけ）

## 2. ロビーのアイコンを変更する
### 理由
ロビーの「👑 上位帯」「🌱 中初級帯」が、参加者バッジの「👑 常連」「🌱 ライト」と同じ絵文字で被っている（ユーザー決定 2026-11-28）。

### やること
- [ ] 上位帯ロビーのアイコンを 👑 → **💎** に、中初級帯ロビーのアイコンを 🌱 → **🍀** に変更する
- [ ] 対象はロビーを表す表示すべて。確認済みの所在：`recruitmentStatus.js` の `buildDayBanner`（lobbyLine の引数）、`embeds.js` の `applyDayCardState`（フィールド名）、`handlers/jobs/eventNotify.js` のリマインド文中のロビー行。他にもロビーを表す使用箇所があれば同様に置き換える
- [ ] 参加者バッジ側の絵文字（🔰・🌱ライト・👑常連など）は変更しない。ランキングのメダル、長者番付のタイトル、ウェルカム文など、ロビーと無関係な 👑 の使用箇所も変更しない

## 3. 都度募集カード：参加者バッジのアイコンを出さない
### 現状の問題
都度募集カードは `getPlayerActiveMark` の印（👑・🔰・🌱・⏳・🎖️）を参加者名に付けている（表示は `embeds.js` の `getMark`、バッジの生成は `handlers/buttons/recruitCard.js`、`handlers/commands.js`、`utils/recruitmentLedger.js` の metadata 再構築）。指示文39の修正で戦績が正しく数えられるようになった結果、常連の人に👑が付いて見えるようになった。

### やること（ユーザー決定 2026-11-28）
- [ ] **都度募集のカードでは、参加者バッジのアイコンを一切出さない**（👑だけでなく🔰・🌱・⏳・🎖️も含め全て非表示）
- [ ] 定期カスタム（土曜・日曜）の表示は現行どおり（🔰・🌱のみ表示、👑等は非表示）で変更しない
- [ ] 実装方式は表示側で出さない形を基本とする。バッジ情報が内部処理（不足情報の再取得判定など）で必要な場合は内部データは残し、表示だけ止める。内部処理が壊れる場合は、その旨を報告して止まること

## やらないこと
- 参加者行の形式（メンション・ランク・レーン表記）の変更
- 経験バッジの判定基準（戦績の数え方）の変更
- ポータル側の表示変更（対象は Bot のカードのみ）

## 完了条件
- 土曜カードで、ロビーごとの人数がバナーにだけ出て、見出し・小見出しと重複しないこと
- 土曜カードと判定・リマインド文のロビーアイコンが 💎／🍀 になっていること
- 都度募集カードの参加者名にバッジアイコンが付いていないこと
- ローカルで Bot の構文チェック（既存の dry-run 手順）が通ること
- 変更前後の表示例を DAILY_LOG に残すこと。ユーザーの指示・合意があったかのような記述はしないこと（根拠は本指示文）
