# 指示文31: Bot棚卸しからの使い勝手改善（代理追加一本化・文言統一・20:00判定の自動化・未設定者への案内・出所不明ボタンの調査）

作成: 2026-11-23（Muse）
対象: 03_SYSTEMS/ktm_bot
経緯: Bot全棚卸し（`~/workspace/goals/ktm/files/ktm-bot-inventory-2026-11-23.md`、内容はリポジトリ外の調査資料。要点は本指示文内に記載）を受けて、ユーザーが 2026-11-23 に実施項目を選定した（候補1・2・3・4・6を実施、5の週間レポートは停止のまま）。

## やること

### 1. 代理追加の二重実装を一本化する
- 現状：代理追加が2方式ある。管理セレクトの `proxy_add_init:<owner>` は periodicRecruit 側のユーザーセレクト方式に読み替えられてそちらが処理し、recruitCard 側の名前入力モーダル方式（`proxy_add_modal:`）には到達できない。しかもモーダルの送信ハンドラ自体が `modals.js` に存在せず、開けても「不明な操作です」になる。
- 対応：動いているユーザーセレクト方式に一本化し、到達不能なモーダル方式の残骸（定義・ルーティング・参照）を撤去する。撤去前に、他から参照されていないか全体を確認すること。

### 2. リマインド文言の表記統一（指示文28の漏れ）
- `src/handlers/jobs/eventNotify.js` のリマインド文言に「低ランク」という表現が残っている（例：「初心者・低ランクでも安心して参加できます」）。
- 募集カード側で統一済みの表記（「中初級帯」「推定MMRランク」）にそろえること。同種の旧表記が他ファイルにも残っていれば、あわせて洗い出して直す（対象箇所を報告に列挙）。

### 3. 20:00開催判定「観戦者への参加お願い」の後を自動化する
- 現状：判定 (A-3) で観戦希望者に「✅で返事を」とお願いを投稿するが、その後の開催確定は主催者の手作業になっている。
- 対応：お願いした観戦者が必要人数分そろったら、「開催確定」を自動で投稿できるようにする（参加者へのメンション付き、既存の開催確定 (A) と同じ形式）。
- 実装方式は既存アーキテクチャ（HTTPインタラクション方式）に合う形を選ぶこと。リアクションの検知がこの方式では難しい場合は、お願い投稿に「参加します」ボタンを付け、押下＝参加者として数える方式でよい（既存の参加処理を再利用）。方式の選択理由を報告すること。
- ガード：対象はお願いを出した観戦者本人の応答のみ。21:00 を過ぎたら自動確定はしない（従来どおり主催者判断に残す）。二重投稿防止の既存ガードと矛盾しないこと。

### 4. 参加時に、プロフィール未設定の人へだけ設定の案内を出す
- 参加ボタンで参加が成立したとき、その人の Portal プロフィールで主要な希望設定（希望レーン、格上との関わり方）が未設定なら、参加完了の応答に設定ページへの案内を1回だけ添える（全員に毎回出すのではない）。
- 判定に必要なデータが Bot の既存の取得経路（バッジ付けで引いている名簿データ等）で得られる範囲で実装すること。得られない場合は、無理に新しい取得経路を作らず、その旨を報告すること。
- 辞退・参加形態の変更のときは出さない。

### 6. 出所不明のボタン4系統を調査して報告する（実装はしない）
- `bet_team:`、`opgg_scout`、`approve_knowledge:`、`quick_substitute_*` の4系統は、ボタンの生成箇所が Bot 内に無い。
- どこで生成されているか（Portal のフロントエンド、他の仕組み等）、押したときの処理が最後まで通るかを調査し、結果をファイル（`03_SYSTEMS/ktm_bot/docs/reports/31-unknown-buttons-investigation.md`）で報告すること。直すかどうかは報告を見て判断する。
