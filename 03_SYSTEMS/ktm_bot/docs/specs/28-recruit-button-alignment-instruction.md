# 指示文28: Discord募集の参加ボタンまわりをPortalの現仕様に合わせる

作成: 2026-11-22（Muse）
対象: 03_SYSTEMS/ktm_bot（定期募集カードと参加ボタンまわり。主に `src/handlers/buttons/periodicRecruit.js` と `src/handlers/jobs/periodicCards.js`）
経緯: ユーザー要望（2026-11-22）「カスタム参加ボタン押下時の処理などを今の仕様に合わせたい」。Portal側では SPEC 10 で帯分けが入り、プロフィール設定も SPEC 18 で刷新されたが、Discord側の募集・参加フローはそれ以前の前提のまま残っている可能性がある。

## Portal側の現仕様（合わせ先）
- 帯分けは **Portal MMR 基準**：MMR 1450 を境に上位帯／中初級帯（SPEC 10、値はユーザー採用済み）。
- 格上まわりの本人の意思は **Portalプロフィール設定** が正本：対面保護（同じ試合で格上と対面するか）と、帯の繰り上げ参加（3択：混ざってもいい／人不足ならOK／自分の帯のみ）。
- 格下サポートは運営側フラグ（バランサー画面で責任者が立てる）。
- 表示の呼び方は「推定MMRランク」に統一予定（Portal指示文27と連動）。

## やること
- [ ] **現行フローの洗い出しと食い違いの報告**：参加ボタン押下時の現在の処理（参加者行へのバッジ付け、そのMMR・ランクの取得元、格上サポート分岐「別レーンをお願いしたい／他のメンバーを招集してほしい／挑戦してみたい」の発動条件、「あと1名」通知、参加形態タグ等）を一覧化し、Portalの現仕様と食い違う点を報告する。
- [ ] **文面・表記の統一**：募集カードと参加ボタンまわりの文面に出るランク・帯・MMRの呼び方を、Portal側の現行表記（中初級帯／推定MMRランク等）にそろえる。
- [ ] **二重に聞かない**：参加時の格上サポート分岐など、Portalプロフィールで既に本人が設定済みの意思（対面保護・繰り上げ）を、Discord側で重ねて聞いたり矛盾する扱いをしたりしていないか確認し、矛盾があればプロフィール設定を優先する形に直す（具体的な直し方は洗い出し結果と一緒に報告し、大きな変更は判断を仰ぐ）。

## やらないこと
- Portal側の仕様（帯の値・プロフィール設定・バランサー）の変更。
- 募集の時刻・曜日・開催判定などの運用ルールの変更。
- Bot の他の機能（カジノ連携、メンター通知等）の変更。

## 未決事項
- 格上サポート分岐を、プロフィール設定への一本化で置き換えるか、Discord側のその場の希望として併用するかは、洗い出しの報告を見てユーザーが決める。決めずに報告すること。

## 完了条件
- 洗い出し結果と食い違いの一覧が報告されていること。
- 文面・表記の統一が入り、Bot が正常にデプロイできる状態であること（デプロイ方法は既存の手順に従う）。
