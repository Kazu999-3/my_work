# SPEC 16：カジノ・大会・メンター等の操作性改善

## 目的
カジノ、お祭りピック（大会）、メンターシップ、ガイドの各ページで、「操作の順番や結果が分からない」「状態（読み込み中・空・条件未達）の案内がない」ために一般メンバーが迷う箇所を直す。2026-11-22 の監査（portal-ux-audit-browser.md／portal-ux-content-audit-code.md）の指摘に基づく。機能仕様は変えず、操作フローと状態案内・条件説明の改善に限る。

## やること

### 1. カジノ（/casino）— ベットの確認と条件説明
- [ ] 勝敗予想ベットの送信に確認ステップを追加する。現在は確認なしでコインが即時確定する（casino/page.tsx の handlePlaceBet）。購入・スクラッチには既に確認があるので、出し方をそれらに揃え、金額・対象・確定後に取り消せないことを確認できるようにする
- [ ] ベットフォーム内に「負けた場合は賭け金が戻らない」旨を明示する（現在は勝った場合の見込み表示のみ）
- [ ] 「サーバー共有ジャックポット金庫: —」の表示（「—」が何を意味するかを含む）と、「ペンタキルで総取り！」の条件・金額の説明を、カジノページ上に表示する
- [ ] CoinGuide の「賭け金 × 2倍 配当」表記が、ルールページの実仕様（パリミュチュエル方式、オッズ 1.15倍〜10.0倍）と矛盾しないか確認し、実態に合わせて修正する
- [ ] カジノ本体ページにも「コインはKTM内でのみ使える遊び用のポイントで、現金等とは交換できない」旨の免責を表示する（現在はルールページの最下部にのみある）

### 2. カジノルール（/casino/rules）— 用語の平易化と重要ルールの見せ方
- [ ] 「期待値」の平易な説明を追加し、「ハウスエッジ」は再登場する箇所（バカラ表の見出し等）でも補足が付く形にする。「還元率（RTP）の読み方」の既存の平易な説明は良い書き方なので維持する
- [ ] ベット上限などの重要なルールを、表の中に埋もれさせず、表の外でも目立つ形で示す
- [ ] 説明のないスラング「ドパガキ」と、無説明の統計用語「二項分布 B(10, 0.5)」を、一般メンバーに伝わる平易な表現に改める
- [ ] 免責文に混入している開発者向け表記（「scripts/casino_rtp_report.js による実測値です」等のスクリプトパス）を、利用者向けの文言に改める

### 3. お祭りピック（/festival/pick）— 操作の順番と数値の根拠
- [ ] 並んでいる操作ボタン（今週:未定、テーマおまかせダイス、大会式ドラフト、1枚プレビュー、設定共有、一時保存など8個）に、押す順番が分かる案内（番号・手順の表示等）を付ける。管理者だけが使う操作は、その旨が分かる表示にする
- [ ] 抽選方式の違い（1体抽選／5体抽選、少人数ドラフト抽選、大会式ドラフト、テーマおまかせダイス）の説明を、初期状態で閉じた折りたたみ（details）の中だけでなく、方式を選ぶ場面で違いが分かるようにする
- [ ] 「外す（❌）」が「ピック候補からの除外」であることを、操作する場所自体で分かるようにする（現在は冒頭の説明文にのみ記載があり、ボタン側ではBANとの区別がつかない）
- [ ] 「必要:18体」「残り173体 (OK)」などの数値表示に、その根拠（なぜその体数が必要か）が分かる説明を付ける
- [ ] 1体抽選／2択／3択★などの選択肢にある「★」の意味を説明する
- [ ] 参加人数スライダーと 1v1〜5v5 ボタンの関係（それぞれが何を決めるのか）を説明する
- [ ] 「大会式ドラフト」のピック順表記（B1➔R1,R2➔B2,B3...）と、LCK/LPL 等の略称に補足を付ける
- [ ] 一時保存・復元の仕組みを本文で説明する（保存先はこのブラウザのみで、別端末では復元できないこと。現在は title 属性のホバー頼み）

### 4. メンターシップ（/mentorship）— 呼称の整理と状態案内・申し込み導線
- [ ] 同一画面で混在する呼称（メンターシップ／師弟／師匠・弟子／先輩・後輩／バディ、および申請の呼び名である オファー／申請／リクエスト／お見合い便）を整理する。統一先は未決事項で決めてから反映する
- [ ] 「後輩としてカードを作成」と「弟子カードを登録」が、同じ操作なのか別操作なのかが分かる表示にする
- [ ] タブに表示される「取得中」を、読み込み中であることが分かる表示に改める
- [ ] 先輩一覧の読み込み中表示と、0件時（空状態）の案内を出し、あわせて「誰に・どう申し込むか」の導線を示す（現在は読み込み中の表示だけで案内がない）
- [ ] 「初回ボーナス +500コイン」の受け取り条件と、「アクティブのみ (60日以内)」という条件の意味を説明する。あわせて、ボーナス金額の表記が場所によって異ならないか（定数表示と実数表記の揺れ）を確認する
- [ ] 「お見合い便」が何か、なぜ自分に届いたかが分かる説明を、届いた側に表示されるバナーにも付ける（現在は相性スコアの表示のみ）
- [ ] 師匠引き受け時のメッセージ入力を、ブラウザ標準の prompt() から、他の申請と同じ専用モーダル形式に揃える。キャンセルした場合は引き受け自体が中止になることも画面上で説明する
- [ ] エラー表示（「自己紹介カードの取得に失敗しました」「エラーが発生しました」等）に、再試行方法など次に取る行動の案内を付ける

### 5. ガイド（/guide）— 冒頭文とFAQの注釈
- [ ] 冒頭の説明文が途中で切れて見える問題を直す
- [ ] FAQ 内に出てくる用語（Pity消費・格上・帯）に、その場で意味が分かる注釈を付ける（用語集そのものの新設は SPEC 14 の範囲）
- [ ] タイトル「KTM 総合使い方ガイド ＆ リリースノート」と内容の不一致を直す（タブ・各タブ内にリリースノート相当の項目が見当たらない）
- [ ] ガイドの説明が旧来の「格上との対面」だけで、新しい「上の実力帯への繰り上げ参加」に触れていない点に説明を追加する（設定自体の整理は SPEC 12 の範囲）

## やらないこと
- 用語集の新設と、全ページを通じた呼び名・通貨単位の統一（SPEC 14 の範囲）
- サイドバー等の導線追加とページ名の整理（SPEC 15 の範囲。カジノへの導線がない件、カジノの名称混在はこちら）
- バランサーとプロフィールの改善（SPEC 12 の範囲）
- 狭幅レイアウトの修正（お祭りピックの大会ドラフトモーダルの幅など。SPEC 17 の範囲）
- カジノのルール・確率・配当計算そのものの変更（本SPECは表示・説明・確認フローのみ）
- ベット、ピック抽選、メンターシップの機能仕様の変更

## 完了条件
- ベットの前に確認ステップが表示され、金額・対象・取り消し不可が確認できる
- ジャックポットとペンタキル総取りの条件・金額が、カジノページ上で読める
- /casino/rules で期待値・ハウスエッジの意味が分かり、ベット上限が表の外でも確認できる
- /festival/pick で、操作の順番と管理者用操作の区別が画面上で分かり、「必要:18体」等の数値に根拠説明がある
- /mentorship で、先輩一覧の読み込み中・空状態に案内があり、申し込み方が画面から分かる
- /guide の冒頭文が切れずに表示され、FAQ の用語（Pity消費・格上・帯）に注釈がある
- ローカルで `npm run build`（04_PORTAL）が成功してからプッシュする

4. /guide の用語注釈の付け方（その場の括弧書きで完結させるか、SPEC 14 の用語集へのリンクにするか）
