# SPEC 12：バランサー／プロフィールの見直し

**v2（2026-11-22 改訂）：監査結果を吸収した改訂版** — ブラウザ実地UX監査（portal-ux-audit-browser.md）とコード監査（portal-ux-content-audit-code.md）のうち、バランサー／プロフィール／結果登録まわりの指摘を取り込んだ。元の4項目（格上2設定の整理、プロフィール設定のグルーピング、バランサー運営要素の分離、結果登録の管理者チェック復活）は維持している。

## 目的
機能追加が積み重なって複雑になったバランサー画面とプロフィール設定を整理し、メンバーと運営の双方にとって分かりやすい状態に戻す。2026-11-22 のコード監査（balancer-profile-review-points.md）と、同日のUX監査2件（ブラウザ実地・コード）の指摘に基づく。ユーザーは「全部直したい」と決定済み。

## やること
1. **「格上許可」の2設定の整理（プロフィール）**
   - 既存の `allow_higher`（同一試合内での格上対面の許可）と、SPEC 10 の `tier_promotion_pref`（上の帯への繰り上げ許可）は、名前と概念が近く混同しやすい。
   - プロフィール上で1つの「カスタム参加の希望」セクションにまとめ、2つの設定の違いが一目で分かる表示名と説明文に改める。
   - 設定の意味・保存先・既存データは変更しない（表示と説明の整理のみ）。
   - あわせて、アコーディオンの要約文だけに残っている内部呼称「こだわり度」を、中身の見出し（希望レーンの強さ等）と揃える（PlayerSettingsPanel.tsx:446,449）。
   - 両設定の"守り"選択肢が同じ🛡️アイコン＋似た言い回しで重複に見える点（同:515,554）も、アイコンか文言で区別できるようにする。
2. **プロフィール設定のグルーピング**
   - 「最初に設定するもの」（IGN、第1・第2希望レーン、NGレーン）と「あとで変えるもの」（参加の希望、プレイスタイル、外観・ダークモード）に分け、初期表示を軽くする（後者の折りたたみ等）。
3. **プロフィール内の説明不足の解消**
   - NGレーン／NG1・NG2 の意味（「絶対に入りたくないレーン」であること）を、その場で分かる説明にする。あわせて、NGを2つ設定済みの状態で3つ目を選ぶと古い方が外れる挙動の説明も添える（PlayerSettingsPanel.tsx:400,430）。
   - 「現在の帯」の表示に、帯の意味の説明を添える（なぜMMR 1450で分かれるか、上位帯のメンバーに繰り上げ設定がどう効くか）（同:475-478）。
   - 「タップで即時反映」の項目と「保存ボタン必須」の項目が混在している点について、パネル冒頭に総括説明を置き、保存成功文の「次回のカスタムから即時反映されます」という矛盾した言い回しを実態に合わせて直す（同:591,667,692）。
   - Discord ID の取得方法の説明がない箇所に、取得手順への案内を添える。
4. **バランサー画面の運営要素の分離**
   - 管理者パネル、格下サポートフラグ、Discordボイス操作バー、Gap診断など運営向けの要素を運営用エリアに寄せ、参加者向けの名簿・チーム結果を主役にする。
   - 機能自体は削除しない（配置と出し分けの整理のみ）。
5. **バランサー冒頭の目的説明と手順ガイドの表示（致命的指摘への対応）**
   - ページ冒頭はタイトル「チーム分けバランサー」だけで、何をするページか・誰がいつ何を操作するかの説明がない（BalancerHeader.tsx:55）。冒頭に目的説明を置く。
   - 定義だけされて画面に出ていない手順ガイド UsageGuide（PageSections.tsx:48-79「3秒でわかるチーム分け手順」）を、実際に画面へ表示する（既存部品の流用でも、同等の新規表示でも可）。
   - 帯分けの仕組みの説明が運営ツール内（管理者のみ・初期状態は閉）にしかない点も、一般メンバーが自分の帯バッジの意味を知れるよう、冒頭説明か手順ガイド側に一般向けの説明を含める。
6. **バランサーの重複ボタンと文言の整理**
   - 同じ操作の重複を解消する：「チーム分け実行」が上部（オレンジ）と下部（緑）の2か所、「🎲 お祭り」も BalancerHeader と QuickActionBar の2か所にある。1か所に一本化する。
   - 「🎲 お祭り」はボタン文言だけでは何が起きるか分からず、意味はホバーの title 頼み。その場で分かる文言か補足を付ける。
   - 格下サポートのスイッチ文言「格下ON ✓／格下OFF」は方向が逆に読め、意味はホバーでしか分からない（PlayerListTable.tsx:251）。表示文言を、押すとどうなるかが文言だけで分かる形に直す。※フラグの永続化そのものは指示文13で対応するため、ここでは表示文言のみ。
   - 下位帯プレイヤーに帯名でなく「🌟混／🛡️専／🤝補」の1文字バッジしか出ない点（同:264-275）を、自分の帯と設定の意味が分かる表示にする。※帯の正式な呼び名の統一（下位帯／中初級帯）は SPEC 14 で扱うため、ここでは意味が伝わる表示に留める。
   - NG・「2:TOP」等の略語はヒント行だけでなく、その場で意味が分かる説明にする。
   - 「参加: 10/10人」の分母や、接戦度（例：94点）の目安が分かる表示にする。
   - エラー文・案内文に混入している開発者向け英語「Active」「Rebuild」を、利用者向けの文言に置き換える（page.tsx:240,306,223,295 ほか）。
7. **結果登録の管理者チェック復活**
   - 2026-11-21 のコミット 8081135 で撤廃された /balancer/record と保存APIの管理者チェックを復活させる。試合結果はMMRに直結するため、登録できる人を元に戻す。
   - ※この撤廃がユーザー本人の意図した開放だった場合は、この項目だけ対象外とする（DAILY_LOG等でなくユーザー確認を正とする）。
8. **結果登録の説明と入力補助の追加**
   - 「試合ID」の意味と入手方法の説明がないため、その場に説明を添える。
   - 「試合時間（18分未満は敗北緩和）」「本日の最終戦（VCステータスをクリア）」は効果の説明自体はあるが、初めての人には用語の意味が取れないため、補足を足す。
   - K/D/A 入力欄に画面上のラベルがなく「0 / 0 / 0」とプレースホルダの K／D／A だけ（TeamStatsTable.tsx:103-129）なので、キル／デス／アシストのラベルを表示する。
   - 保存ボタン（「試合結果を保存してMMR更新」）が無効なとき、何が不足しているか（勝敗の選択、全員の名前など）をボタン付近に案内する。現状は送信時のエラーメッセージで初めて分かる。
   - 「💎 0」ボタン（ペンタキル）の用途が表示だけでは分からないため、用途が分かる表示にする（TeamStatsTable.tsx:134,136）。
   - OCRが埋めなかった項目（視界スコア等）が0のまま送信されることへの注意書きを添える。
   - 「🔁 陣営入替」は入力済みスコアごと反転する操作なのに確認なしで即実行されるため、実行前に確認ダイアログを挟む。
   - 解析中表示の「Gemini APIで対戦結果画像を解析中...」のような開発者向け表記を、利用者向けの文言（「画像を解析中」等）に置き換える。

## やらないこと
- MMR算出・KDA評価・チーム分けロジックの変更
- 帯分けの値（2帯制・MMR 1450・格上3択のデフォルト等）の変更（SPEC 10 の値は別途ユーザーが判断する）
- 既存機能の削除
- 格下サポートフラグの永続化（指示文13で対応。本SPECでは表示文言のみ扱う）
- 用語集の新設・拡充、全ページにわたる呼び名の統一（SPEC 14 の範囲）
- 狭幅（375px等）でのレイアウト対応（SPEC 17 の範囲）
- バランサー／プロフィール／結果登録以外のページの指摘（トップ、/mypage の着地タブ、対戦履歴、リーダーボード、アナライザー、カジノ、大会ピック、メンターシップ等は別SPECの範囲）

## 完了条件
- プロフィールで2つの「格上」系設定の違いが説明文だけで判別でき、アコーディオン要約文に内部呼称「こだわり度」が残っていない
- プロフィールの初期表示が「最初に設定するもの」中心になっている
- プロフィールで NG の意味と挙動、「現在の帯」の意味、即時反映か保存必須かの区別が、画面内の説明だけで分かる
- バランサー画面で参加者向け要素と運営向け要素が視覚的に分かれている
- バランサーの冒頭に目的説明があり、手順ガイドが実際に画面に表示されている
- 「チーム分け実行」「お祭り」ボタンが各1か所に一本化され、「お祭り」の意味がホバーなしで分かる
- 格下スイッチと下位帯バッジの意味が、ホバーなし・文言だけで分かる
- 結果登録で、K/D/A のラベルが表示され、保存ボタンが無効な理由が画面上で分かり、「💎」ボタンの用途と「試合ID」の意味が説明されている
- 管理者チェック復活後、管理者以外は結果登録ができない（復活前後で通常のチーム分け・閲覧に影響がない）
- ローカルで `npm run build`（04_PORTAL）が成功してからプッシュする
