# 指示文：投稿済み師弟スレッドの死リンク遡及修正

作成: 2026-11-20（Muse）
前提: `fix-dead-links-instruction.md` の #1（discordMentorship.ts のリンク先コード修正）が先に完了していること。順序が逆だと、修正後に新規作成されるスレッドへまた死リンクが入る。

## 目的

既に投稿済みの師弟ペアスレッドの歓迎メッセージ内に残っている死リンクを、Bot のメッセージ編集で正しいリンクへ置き換える。

- 対象リンク（現状）: `https://my-work-8jbd.vercel.app/coach`（404）
- 置換後: `https://ktm-pilot.vercel.app/coach`

## 対象

- Discord フォーラム（コーチング・質問）の師弟ペアスレッドの**開始メッセージ**（Bot 投稿の歓迎埋め込み）
- 判定条件: 埋め込みの説明文に `my-work-8jbd.vercel.app/coach` を含むもの
- スレッドIDの入手: 師弟マッチの記録（DB）にスレッドID/リンクがあればそれを使う。無ければフォーラムチャンネルのスレッド（アクティブ＋アーカイブ済み）を Discord API で列挙する

## 手順（ドライラン → 承認 → 本適用の順を厳守）

1. **ドライラン（書き換え禁止）**
   - 対象スレッドを列挙し、件数と内訳（アクティブ／アーカイブ済み）を報告する
   - サンプル1件について、変更前と変更後の埋め込み内容の差分を報告する
   - この時点で止まり、ユーザーの承認を待つ
2. **本適用（承認後）**
   - 各スレッドの開始メッセージを取得し、埋め込み内の該当URL**だけ**を置換して PATCH する
   - 文面・メンション・他リンク（/mypage）・コンポーネントは一切変更しない
   - Discord のレート制限に配慮し、リクエスト間に間隔を空ける
3. **報告**
   - 成功／失敗／スキップの件数と、適用後に数件を目視確認した結果を報告する

## 前例・実装メモ

- `scripts/update_mentorship_threads_announce.js` が同じ方式（Bot トークンでスレッド内の Bot メッセージを PATCH）の実績あり。これを土台にしてよい
- Bot トークンは `04_PORTAL/.env.local` の `DISCORD_BOT_TOKEN` を使う。**トークンの値をログ・Git・チャット・DAILY_LOG に絶対に出さないこと**

## 対象外

- 記事承認ボタンの過去メッセージ（ほぼ承認済みで実益が薄いため対象外。新規分は別指示で修正済み）
- ユーザーが投稿したメッセージ（Bot には編集権限がない）

## 未決事項（勝手に決めない）

- アーカイブ済みスレッドの扱い: 編集するとアーカイブが解除される場合がある。ドライランで件数を報告し、含めるかどうかはユーザーの判断を仰ぐこと

## 完了条件

- ドライラン報告 → ユーザー承認 → 本適用 → 結果報告、の順に完了していること
- コード修正（別指示）と違い、これは一回限りの運用スクリプトなので、実行後にスクリプトを残すかどうかは報告に含めて提案すること（勝手に削除しない）
