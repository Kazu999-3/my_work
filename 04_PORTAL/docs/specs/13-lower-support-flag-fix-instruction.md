# 指示文13：格下サポートフラグの永続化と操作UIの修正

## 背景（2026-11-22 本番確認とコード確認で判明）
SPEC 10 の「格下サポート」（上位帯の特定の人だけが下の帯に参加できる）は、本番で運用できる状態になっていない。

1. **フラグが保存されない。** `usePlayerRoster.ts` はプレイヤー読み込み時に全員 `allow_lower_support: false` で初期化しており、DB（migration 140 で追加した列）の値を読み込んでいない。さらに `handleInputChange` はこのフィールドを変更しても保存処理を呼ばない（コメントに「DBに保存しない一時フラグ」と明記）。つまりページを再読み込みするたびに指定が消え、「特定の人をあらかじめ指定しておく」運用ができない。
2. **操作部品と分からない見た目。** `PlayerListTable.tsx` のトグルは、管理者かつ上位帯かつ参加中の行でのみボタンになるが、表示文言は「上位帯」という帯ラベルそのもので、クリックできることが見た目で分からない（説明は title 属性のみ）。2026-11-22 の本番確認でも、操作部品として認識できなかった。

ユーザーの決定（SPEC 10）は「格下は特定の人に限る」であり、指定は継続的に効く前提である。この2点を直す。

## やること
- [ ] プレイヤー読み込み時に、DB の `allow_lower_support` の値をそのまま使う（false で上書きしない）
- [ ] フラグの変更を、他のプレイヤー設定と同じ保存経路で DB に保存する（保存用APIがこのフィールドを受け付けていない場合は、受け付けるよう拡張する）
- [ ] トグルの見た目を、状態と操作可能性が分かる表示にする（例：「格下サポート OFF／ON」のように状態語を含める）。管理者以外には従来どおりラベル表示のままでよい
- [ ] 永続化したフラグで、帯分け編成とオフレーン制限（tierBand.ts 経由）が従来どおり効くことを確認する

## やらないこと
- 帯の数・MMR 1450 の閾値、格上繰り上げの優先順位、オフレーン制限の2段階ルールの変更
- フラグを付けられる条件（管理者のみ・上位帯・参加中）の変更
- SPEC 12（バランサー／プロフィール見直し）の範囲の変更

## 完了条件
- 管理者がフラグを ON にしてページを再読み込みしても ON のまま残っている
- 管理者以外にはトグルが表示されず、従来の帯ラベルのみが見える
- フラグ ON の上位帯プレイヤーが下位帯の編成候補に入り、オフレーン制限が効く
- ローカルで `npm run build`（04_PORTAL）が成功してからプッシュする
