# SPEC：読み込み表示の改善（KTMポータル）

対象：https://my-work-8jbd.vercel.app/history 、 https://my-work-8jbd.vercel.app/mentorship
Antigravityへの渡し方：このファイルをリポジトリに置き「このSPECを読んで実装して」と指示する。

## 1. 目的
データ表示まで数秒かかるページで、利用者が「壊れている / 0件だ」と誤解しないようにする。

## 2. 現状の問題（2026-11-19 本番確認）
- /history：開いた直後は「戦績データを読み込み中...」のみが表示され、内容が出るまで約8秒かかった
- /mentorship：最初は件数が 0 / 0 / 0 で「自己紹介カードを読み込み中...」と表示され、約8秒後に後輩7・先輩6・ペア6が表示された。読み込み中なのに「0件」に見えるのが特に誤解を招く
- /festival/pick も読み込み直後はアイコンが灰色プレースホルダーの期間がある

## 3. やること
- [ ] スケルトン表示を入れる：/history は試合カードの形、/mentorship は自己紹介カードの形のスケルトンを、実際のレイアウトと同じ寸法で表示する（レイアウトシフトを起こさない）
- [ ] 件数表示の扱いを直す：読み込み中は件数を出さないか「取得中」と表示し、確定後に実数を出す。読み込み中に 0 と表示しない
- [ ] 状態を3つに分ける：読み込み中 / 取得成功（0件なら本当の空状態として理由と次のアクションを表示）/ 取得失敗（エラーメッセージ＋再読み込みボタン）。現状の勝敗予想ページの空状態（理由付き）は良い例なので文案のトーンを揃える
- [ ] タイムアウトを設ける：目安10秒を超えたら失敗状態に切り替え、無限に「読み込み中」にしない
- [ ] （可能なら）取得自体の高速化も検討する：初期表示に必要なデータだけ先に取る、キャッシュする等。やる場合は変更内容と効果を報告する

## 4. やらないこと
- データ取得先・データ構造の変更（高速化で必要な場合は事前に報告）
- ページのデザイン刷新

## 5. 完了条件
- [ ] /history と /mentorship で、開いてから表示までスケルトンが出続け、0件と誤解されない
- [ ] 通信を切った状態で開くと、失敗メッセージと再読み込みボタンが出る
- [ ] 本当に0件のときは、空である理由が分かる文案が出る
- [ ] 表示完了時にレイアウトが大きくずれない

## 6. 未決事項（エージェントが勝手に決めない）
- 高速化のためにデータ取得方式を変えるかどうか（変える場合は方式の選択肢を提示して止まる）
