# SPEC：数字と表記の統一（KTMポータル）

対象：https://my-work-8jbd.vercel.app
Antigravityへの渡し方：このファイルをリポジトリに置き「このSPECを読んで実装して」と指示する。

## 1. 目的
ページごとに食い違っている数字・単位・表記を正本に統一し、利用者の混乱と不信をなくす。

## 2. 現状の問題（2026-11-19 本番確認）
1. 初回特典の表記が3通りある
   - トップ： 「初回+500pt進呈中」
   - /mentorship： 「初回ボーナス +500コイン」
   - /guide： 「初期 1,000コインの自動付与」
2. ロール表記揺れ： /leaderboard の名簿で大半は「JG」だが、一部メンバーは「JUNGLE」と表示される
3. /history の見出しは「最新30件の試合結果とMMR変動履歴」だが、初期表示は約50件。下部ボタンは「さらに過去の試合を読み込む (+30件)」
4. チャンピオン総数の不一致の疑い： /festival/pick は170体（ページ内訳合計も170で整合）。一方、関連アプリ「戦術パイロット」は全175体を掲げている。ポータル側に未追加チャンピオンがいる可能性を確認する

## 3. やること
- [ ] 特典の正本を確認する：実際に付与している処理（コード / DB / Bot側）の値と単位を正とし、全ページの文案をそれに統一する。文案側を推測で書き換えない
- [ ] 特典の値と単位はハードコードをやめ、共通定数（または設定値）1か所から参照する形にする。再発防止が目的
- [ ] ロール表記を正規化する：表示は「JG」に統一。保存データ側に「JUNGLE」等が混在する場合は、表示時の正規化マップで吸収し、データ移行が必要なら移行内容を報告してから行う
- [ ] /history：初期表示件数と見出しを一致させる。初期件数を30件に揃えるか、見出しを実件数ベースの文案（例：「試合結果とMMR変動履歴」＋動的件数）に変更する。どちらにしたか報告すること
- [ ] チャンピオン数を確認する：ポータルのチャンピオンデータの出典と最終更新を確認し、170体で正しいのか、追加漏れがあるのかを切り分ける。追加漏れがある場合は、不足分をリスト化して報告し、データ追加は別途確認を取ってから行う（このSPECでは文案の数字だけを175に書き換えない）

## 4. やらないこと
- 特典の金額・付与ロジック自体の変更
- チャンピオンデータの無断追加・削除
- デザインやレイアウトの変更

## 5. 完了条件
- [ ] 全ページで特典の値・単位が一致している（対象ページを列挙して報告）
- [ ] 名簿・順位表でロール表記が「JG」に統一されている
- [ ] /history の見出しと初期表示件数が一致している
- [ ] チャンピオン総数について「170が正 / 追加漏れあり」のどちらか結論が出ている

## 6. 未決事項（エージェントが勝手に決めない）
- 特典の正しい値と単位（500pt / 500コイン / 1,000コイン のどれが実際の付与か）
- チャンピオンデータの正本（どのソースを正とするか）
