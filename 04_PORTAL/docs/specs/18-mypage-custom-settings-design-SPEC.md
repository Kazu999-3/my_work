# SPEC 18（v4）：マイページのカスタム関連設定のデザイン刷新

## 目的
マイページ（プロフィール設定）の中でも、カスタムのチーム分けと帯編成に直接効く設定群を、初めてのメンバーでも迷わず設定できるデザインに作り替える。方針はユーザーが選んだ「案2：カードでまとめる」——設定項目と値は今のまま全て残し、テーマごとのカードに整理する。v4 では各カードの中の「選び方」に、縦横の軸で選ぶ方式（ユーザーの提案）を追加する。あわせて、デザイン面の原則（状態設計・一貫性・手触り）も取り込む。

## デザイン方針（2026-11-22 ユーザー決定＋参考資料からの原則）
1. **カードでまとめる**：関連する設定をテーマごとのカードにまとめ、各カードに「何の設定か」の一文を付ける。項目の統合やプリセット化はしない（細かい組み合わせは今まで通り可能に保つ）。
2. **軸で選ぶ**：複数の設定が表形式で表せるものは、縦横の軸を持つグリッドで選べるようにする（レーン希望の表、格上の2軸グリッド）。軸の各段階は既存の選択肢と1対1で対応させ、新しい値を増やさない。
3. **状態を全部設計する**：読み込み中（骨組み表示）、未設定（空）状態、保存中、保存完了、保存エラーの各状態に、見た目と次の行動の案内を用意する。エラー時は入力した選択を保持し、再試行できるようにする。
4. **一貫性を正本で守る**：用語・色・部品の使い方は SPEC 14 の統一と既存ポータルの見た目に合わせ、画面ごとに違う言い回しや見た目を作らない。AI が作りがちな画一的で浮いたデザイン（過剰な装飾など）に寄せない。
5. **手触りは控えめに**：保存完了など、変化が伝わる場面にだけ短い遷移を付け、過剰なアニメーションは入れない。

## 対象の設定（カスタムに影響するもの）
- 第1希望レーン／第2希望レーン
- NGレーン（NG1・NG2 を含む）
- 希望レーンの強さ（レーン優先度）
- 対面保護（同じ試合での格上対面の可否）
- 帯の繰り上げ許可（格上許可の3択）

※格下サポートフラグは運営側が付ける設定なので対象外（指示文13で対応）。外観・テーマ等の設定も対象外（ただし配置の整理上、別カードに分けることは対象に含む）。

## SPEC 12 との関係
SPEC 12 のプロフィール側の項目（格上2設定の整理、設定のグルーピング、説明不足の解消）と重なる部分は、本 SPEC を優先する。SPEC 12 側では、その部分は本 SPEC で対応済みとして読み替えてよい（バランサーの運営分離、結果登録の管理者チェック復活など、その他の項目は SPEC 12 のまま）。

## やること
### カード構成
- [ ] カスタム関連の設定を、次の2カードにまとめる（カード名は案。最終名は未決事項）
  - カード「レーンのこと」：希望レーン（第1・第2）、NGレーン、レーン優先度
  - カード「格上との関わり方」：対面保護、帯の繰り上げ許可
- [ ] 各カードの冒頭に、そのカードが何を決めるものかの一文説明を付ける（例：レーンのこと＝「どのレーンで遊びたいかの設定です」）
- [ ] カスタムに影響しない設定（外観など）は、カスタム関連カードと混ざらないよう別のカード／領域に分ける
- [ ] カード内の並び順は「上から順に設定すれば終わる」順にする

### 軸で選ぶUI（カードの中の選び方）
- [ ] レーン希望は表形式にする：縦軸＝レーン（TOP／JG／MID／BOT／SUP）、横軸＝希望の強さ（第1希望／第2希望／どちらでも／NG）。タップでそのレーンの希望を変更でき、全レーンの希望が一目で見える
  - 第1希望は常に1レーンだけになるよう、UI側で制御する（別のレーンで第1希望を選んだら、前のレーンは自動で「どちらでも」等に戻す。戻し先は未決事項）
  - 第2希望・NGも同様に、現行データの制約（NG1・NG2 の扱いを含む）と矛盾しないよう制御する
- [ ] 格上の2設定は2軸グリッドにする：縦軸＝対面（格上と当たるかどうか）、横軸＝帯（上の帯に混ざるかどうか）。マスの位置を選ぶと、対面保護と帯の繰り上げ許可が同時に設定される
  - 軸の各段階は既存の選択肢と1対1で対応させる（帯側は現行の3択：混ざってもいい／人手不足ならOK／自分の帯のみ。対面側の段階数が現行と異なる場合は、現行の選択肢に合わせて段階を作り、新しい値は増やさない）
  - 軸ラベルには、それぞれ何を意味するかの一文を添える
- [ ] グリッドのマスは、幅約375pxの画面でも押し間違えない大きさを確保する（SPEC 17 の狭幅対応と矛盾させない）
- [ ] 軸UIが合わない項目（レーン優先度など）は、無理に表にせず、言葉で分かるボタン形式のままにする

### 各項目の分かりやすさ
- [ ] 各設定に「変えると何が起きるか」の一文説明と具体例を付ける
- [ ] 現在の選択が色だけでなく文言でも判別できるようにする（「選択中」の明示、要約文との連動）
- [ ] 画面の上部に「今のあなたの設定」の要約を文章で表示する（例：「JG優先／格上対面OK／人手不足なら上の帯もOK」のように、現在の設定値から自動で組み立てる）

### 状態と保存
- [ ] 保存の挙動を統一する（即時反映と保存ボタンの混在をなくす）。保存中・保存完了・保存失敗の表示を用意し、失敗時は選択を保持して再試行できるようにする
- [ ] 読み込み中は骨組み（スケルトン）表示にし、未設定の新規メンバーには「まずレーンのことから設定してください」という空状態の案内を出す
- [ ] 用語は SPEC 14 の統一結果に従う（「こだわり度」などの内部呼称は使わない）

## やらないこと
- 設定項目の統合・削減・プリセット化（案1・プリセット案は不採用。項目と選択肢は現行のまま）
- 設定の意味・保存先・既存データの変更（既存ユーザーの設定値はそのまま引き継ぐ）
- バランサー側のチーム分け・帯編成ロジックの変更

## 完了条件
- 初めて見る人が、カードの見出しと一文説明だけで、どこに何の設定があるか分かる
- レーン希望の表と格上の2軸グリッドで選んだ内容が、そのまま従来の各設定値として保存される
- 「今のあなたの設定」の要約が、実際の保存値と常に一致する
- 既存ユーザーの設定値が、デザイン刷新の前後で変わっていない
- 保存失敗の状態を再現しても、選択が消えず再試行できる
- ローカルで `npm run build`（04_PORTAL）が成功してからプッシュする

## 未決事項（エージェントが勝手に決めない）
1. カードの正式な名前と並び順
2. 第1希望を別のレーンに移したとき、前のレーンの戻し先（「どちらでも」か「第2希望」か）
3. 要約文の文体と、設定画面の色・レイアウトの細部
4. 各設定の説明文の最終文案
