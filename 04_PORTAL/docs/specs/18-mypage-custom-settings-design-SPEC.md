# SPEC 18（v2）：マイページのカスタム関連設定のデザイン刷新

## 目的
マイページ（プロフィール設定）の中でも、カスタムのチーム分けと帯編成に直接効く設定群を、初めてのメンバーでも迷わず設定できるデザインに作り替える。v2 では、ユーザーの方針「ひとつひとつ選択させるのではなく、ある程度の項目をまとめる」を軸に、プリセット＋詳細の2層構造に改訂し、デザイン面の原則（状態設計・一貫性・手触り）も取り込む。

## デザイン方針（2026-11-22 ユーザー決定＋参考資料からの原則）
1. **まとめて選べる形にする**：関連する設定は「参加スタイル」のプリセットで一括設定し、個別調整は詳細設定に分ける（2層構造）。
2. **状態を全部設計する**：読み込み中（骨組み表示）、未設定（空）状態、保存中、保存完了、保存エラーの各状態に、見た目と次の行動の案内を用意する。エラー時は入力した選択を保持し、再試行できるようにする。
3. **一貫性を正本で守る**：用語・色・部品の使い方は SPEC 14 の統一と既存ポータルの見た目に合わせ、画面ごとに違う言い回しや見た目を作らない。AI が作りがちな画一的で浮いたデザイン（過剰な装飾など）に寄せない。
4. **手触りは控えめに**：プリセット適用や保存完了など、変化が伝わる場面にだけ短い遷移を付け、過剰なアニメーションは入れない。

## 対象の設定（カスタムに影響するもの）
- 第1希望レーン／第2希望レーン
- NGレーン（NG1・NG2 を含む）
- 希望レーンの強さ（レーン優先度）
- 対面保護（同じ試合での格上対面の可否）
- 帯の繰り上げ許可（格上許可の3択）

※格下サポートフラグは運営側が付ける設定なので対象外（指示文13で対応）。外観・テーマ等の設定も対象外。

## SPEC 12 との関係
SPEC 12 のプロフィール側の項目（格上2設定の整理、設定のグルーピング、説明不足の解消）と重なる部分は、本 SPEC を優先する。SPEC 12 側では、その部分は本 SPEC で対応済みとして読み替えてよい（バランサーの運営分離、結果登録の管理者チェック復活など、その他の項目は SPEC 12 のまま）。

## やること
### 上の層：参加スタイル（プリセット）
- [ ] 対面保護・帯の繰り上げ許可・レーン優先度をまとめて設定できる「参加スタイル」のプリセットを3つ用意する（案：🔥 チャレンジ＝格上対面OK・上の帯にも混ざる・レーンはできれば ／ ⚖️ バランス＝対面は同格まで・人手不足なら上の帯OK ／ 🛡️ マイペース＝対面は同格まで・自分の帯のみ・レーン優先度は強め）
- [ ] 各プリセットに「選ぶとどうなるか」の一文説明を付け、適用前に内容が分かるようにする
- [ ] 現在の設定がどのプリセットに一致するかを表示し、どれにも一致しない場合は「カスタム設定中」と表示する
- [ ] プリセットを選んだら、対象の設定値が一括で更新され、保存まで完了する（途中で個別の確認を挟まない）

### 下の層：個別設定（詳細）
- [ ] 希望レーン（第1・第2）と NGレーンは個人差が大きいので個別設定のまま残す
- [ ] プリセット対象の3項目も、詳細設定として個別に変更できるようにする（変更するとプリセット表示は「カスタム設定中」に切り替わる）
- [ ] 各設定に「変えると何が起きるか」の一文説明と具体例を付ける
- [ ] 並び順は「上から順に設定すれば終わる」順にする（参加スタイル → 希望レーン → NGレーン → 個別の微調整）

### 共通
- [ ] 画面の上部に「今のあなたの設定」の要約を文章で表示する（例：「JG優先／格上対面OK／人手不足なら上の帯もOK」のように、現在の設定値から自動で組み立てる）
- [ ] 選択肢は、意味が言葉で分かるボタン形式にし、現在の選択が色だけでなく文言でも判別できるようにする（「選択中」の明示）
- [ ] 保存の挙動を統一する（即時反映と保存ボタンの混在をなくす）。保存中・保存完了・保存失敗の表示を用意し、失敗時は選択を保持して再試行できるようにする
- [ ] 読み込み中は骨組み（スケルトン）表示にし、未設定の新規メンバーには「まず参加スタイルを選んでください」という空状態の案内を出す
- [ ] 用語は SPEC 14 の統一結果に従う（「こだわり度」などの内部呼称は使わない）

## やらないこと
- 設定の意味・保存先・既存データの変更（既存ユーザーの設定値はそのまま引き継ぐ。プリセットへの一致表示は表示上の判定のみで、値を書き換えない）
- バランサー側のチーム分け・帯編成ロジックの変更
- 新しい設定項目の追加（プリセットは既存項目の組み合わせであり、新規項目ではない）

## 完了条件
- 初めて見る人が、参加スタイルを選ぶだけでカスタム参加に必要な設定を終えられる
- 「今のあなたの設定」の要約とプリセット表示が、実際の保存値と常に一致する
- 既存ユーザーの設定値が、デザイン刷新の前後で変わっていない
- 保存失敗の状態を再現しても、選択が消えず再試行できる
- ローカルで `npm run build`（04_PORTAL）が成功してからプッシュする

## 未決事項（エージェントが勝手に決めない）
1. プリセットの名前と、各プリセットに含める値の最終組み合わせ
2. 要約文の文体と、設定画面の色・レイアウトの細部
3. 各設定の説明文の最終文案
