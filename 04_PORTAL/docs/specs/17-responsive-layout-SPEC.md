# SPEC 17：狭幅レイアウトの修正

## 目的
KTM Portal を約375pxの狭幅で開いたときに起きるレイアウト崩れを修正し、スマートフォン幅でも各ページの主要操作と表示が使える状態にする。

対象は、コード監査 `portal-responsive-audit-code.md` で挙がった14件（致命的1件・中3件・軽微10件）とする。この監査はコードからの推定であり、実機・実ブラウザでの375px表示は未検証である。そのため、修正後の確認までを本SPECの完了条件に含める。

本SPECはレイアウトのみを対象とする。

## やること

### 優先度：致命的

- [] **/festival/pick：大会ドラフトモーダルの左右パネルを狭幅対応にする**
- 対象ファイル：`04_PORTAL/src/app/festival/pick/FestivalTournamentDraftModal.tsx`
- 375pxで起きる問題：本体が常時横並びで、左パネルと右パネルが各 `w-64 shrink-0` のため、左右だけで512pxを占めて375pxを超過する。モーダルが `overflow-hidden` のため横スクロールもできず、中央のチャンピオン選択プールが幅ゼロ近くまで潰れるか、右パネルが見切れて、ドラフト操作が実質不可能になる可能性がある。
- 修正の方向性：狭幅では左右パネルを縦積み、折りたたみ、または幅を抑えた表示へ切り替え、中央のチャンピオン選択プールに操作可能な幅を確保する。広幅では現在の3カラム構成を維持する。

### 優先度：中

- [] **/balancer：バランス結果モーダルのチームヘッダーを狭幅で縦積みにする**
- 対象ファイル：`04_PORTAL/src/app/balancer/_parts/BalanceResultModal.tsx`
- 375pxで起きる問題：親が `grid grid-cols-1 md:grid-cols-11` なのに、BLUE・VS・REDの子要素は無接頭辞の `col-span-5` / `col-span-1` / `col-span-5` である。`grid-cols-1` に対して `span 5` が暗黙カラムを生成し、意図した縦積みにならず、BLUE/REDの帯が見切れたり不均等になったりする可能性が高い。
- 修正の方向性：`col-span` を `md:` 以上の指定にし、狭幅では1カラムで縦積み、広幅では従来の11カラム構成になるようレスポンシブ指定をそろえる。

- [] **/balancer：レーン対面行を狭幅で縦積みにし、内部の最小幅も収める**
- 対象ファイル：`04_PORTAL/src/app/balancer/_parts/LaneMatchupRow.tsx`
- 375pxで起きる問題：親が `grid grid-cols-1 md:grid-cols-11`、子が無接頭辞の `col-span-5` / `col-span-1` / `col-span-5` で、結果モーダルと同じ仕組みで対面行が崩れる可能性がある。内部の選択エリアにも `min-w-[5.5rem]` があり、選手カード同士の圧迫や見切れが起きる可能性がある。
- 修正の方向性：結果モーダルと同様に `col-span` へレスポンシブ接頭辞を付け、狭幅では縦積みにする。あわせて選択エリアの最小幅が375px内に収まるよう調整する。

- [] **/leaderboard：勝率マトリクスの横スクロール中も行ラベルを判別できるようにする**
- 対象ファイル：`04_PORTAL/src/app/leaderboard/WinrateMatrixPanel.tsx`
- 375pxで起きる問題：テーブルが `w-full min-w-[800px]` で、画面の2倍超の横スクロールが必須になる。先頭列を固定する `sticky` 指定がないため、スクロールすると左端のプレイヤー名が見えなくなり、どの行か分からなくなる。
- 修正の方向性：横スクロールを前提とする場合でも先頭のプレイヤー名列を固定するなど、行を識別できるレイアウトにする。列幅を狭幅向けに見直す場合も、数値の判読性を維持する。

### 優先度：軽微

- [] **/balancer：クイックアクションバーの要素圧迫を解消する**
- 対象ファイル：`04_PORTAL/src/app/balancer/_parts/QuickActionBar.tsx`
- 375pxで起きる問題：`fixed` の下部バー内にタイマー表示とボタンが `whitespace-nowrap` で並び、残る要素が横幅いっぱいに逼迫して、余白がほぼ消えるかラベルが見切れる可能性がある。
- 修正の方向性：狭幅では要素を折り返す、複数行にする、または間隔と幅を見直し、タイマーと主要ボタンのラベルが欠けないようにする。

- [] **/player：戦績テーブル2件の `min-w-[420px]` を狭幅向けに見直す**
- 対象ファイル：`04_PORTAL/src/app/player/[id]/page.tsx`
- 375pxで起きる問題：2件の戦績テーブルが `w-full min-w-[420px]` で、破綻はしないものの約420px分の局所横スクロールが必要になる。
- 修正の方向性：狭幅では主要列が画面幅に収まるよう最小幅や列幅を見直す。横スクロールを残す場合も、対象がテーブル内だけに限定される現行構造を維持する。

- [] **/player：設定パネルの3列ボタンを狭幅で読みやすくする**
- 対象ファイル：`04_PORTAL/src/app/player/PlayerSettingsPanel.tsx`
- 375pxで起きる問題：「希望レーンの強さ」の選択肢が無接頭辞の `grid grid-cols-3` で、各ボタンにタイトルと説明文が入るため、1列あたり約110pxになり、説明文が窮屈に折り返してボタンが縦長化する。
- 修正の方向性：狭幅では1列または説明文が読みやすい列数に切り替え、広幅では現在の選択肢レイアウトを維持する。

- [] **/leaderboard：チャンピオンテーブルの見出し列と使用者セルの最小幅を調整する**
- 対象ファイル：`04_PORTAL/src/app/leaderboard/page.tsx`
- 375pxで起きる問題：見出し列と使用者セルに `min-w-[200px]` があり、`overflow-x-auto` 内でも局所横スクロール量が増える。
- 修正の方向性：狭幅では最小幅を緩和するか、省略・折り返しが効く幅指定にし、横スクロール量を減らす。

- [] **/leaderboard：コインランキングの検索欄と他コントロールの並びを調整する**
- 対象ファイル：`04_PORTAL/src/app/leaderboard/CoinsRankingPanel.tsx`
- 375pxで起きる問題：検索欄が `flex-1 min-w-[240px]` でほぼ全幅を取り、ソート等の他要素が次行に落ちる。動作上の問題はないが、コントロールバーの幅配分が狭幅向けではない。
- 修正の方向性：狭幅では検索欄の最小幅を緩和するか、検索欄と他要素を意図した行分けにし、要素同士が圧迫しないようにする。

- [] **/analyzer：プレイヤー比較ビューの3列統計を狭幅向けに調整する**
- 対象ファイル：`04_PORTAL/src/app/analyzer/PlayerCompareView.tsx`
- 375pxで起きる問題：無接頭辞の `grid grid-cols-3` の統計ブロックで1列あたり約110pxになり、数値は収まると推定されるが、ラベルが長い項目では折り返しが増える。
- 修正の方向性：狭幅では列数を減らすか、余白と列幅を見直し、数値とラベルが読みやすい配置にする。

- [] **/casino：収支ランキング表の `min-w-[420px]` を見直す**
- 対象ファイル：`04_PORTAL/src/app/casino/_casino/ProfitRankingTab.tsx`
- 375pxで起きる問題：テーブルが `w-full min-w-[420px]` でセルに `whitespace-nowrap` があり、約45px分の局所横スクロールが必要になる。
- 修正の方向性：狭幅では最小幅を緩和するか、一部セルの折り返し・省略を可能にし、375px内に収まるようにする。

- [] **/guide：ポータルガイドの表がカード内で僅かに横スクロールしないよう調整する**
- 対象ファイル：`04_PORTAL/src/app/guide/tabs/GuidePortalTab.tsx`
- 375pxで起きる問題：テーブルが `w-full min-w-[320px]` で、表示幅は約351pxあり収まる計算だが、カード内の追加パディング次第では僅かに横スクロールする可能性がある。
- 修正の方向性：テーブル最小幅とカード内余白の合計が表示幅を超えないよう、狭幅向けに最小幅または余白を調整する。

- [] **/ktm-admin：オンボーディングチャンネル表の nowrap セルによる横スクロールを抑える**
- 対象ファイル：`04_PORTAL/src/app/ktm-admin/OnboardingChannelsPanel.tsx`
- 375pxで起きる問題：テーブルは `overflow-x-auto` 内にあるが、時刻・状態バッジ等のセルに複数の `whitespace-nowrap` があり、セルの自然幅の合計が表示幅を超えて局所横スクロールが発生する。
- 修正の方向性：狭幅では重要でないセルの折り返し・省略を可能にするか列幅を見直し、時刻と状態などの主要情報が横スクロールなしで判別できるようにする。

- [] **/player：背景装飾の絶対配置円のはみ出しを抑える**
- 対象ファイル：`04_PORTAL/src/app/player/[id]/page.tsx`
- 375pxで起きる問題：400px幅を含む絶対配置の装飾円が画面右側にはみ出す。`body` の `overflow-x: clip` で切られるため実害は装飾の見切れのみと推定される。
- 修正の方向性：装飾円の幅・位置をビューポート幅に収めるか、親要素側で見切れを前提とした配置にそろえ、本文や操作要素へ影響しないようにする。

## やらないこと
- 文言・用語・説明内容の改善（SPEC 14〜16の範囲）
- バランサーの画面構成や機能仕様の見直し（SPEC 12の範囲）。本SPECでは監査で挙がったレイアウト崩れだけを扱う
- MMR、チーム分け、帯分け、料金・ポイント等の計算や機能ロジックの変更
- 監査で「確認したが問題なし」とされたページ・コンポーネントのレイアウト変更。ただし共通コンポーネントの修正で影響する場合は、影響範囲を確認して報告する
- デスクトップ幅の既存レイアウトを意図せず変えること

## 完了条件
- 上記14件すべてに対応している。対応できない項目がある場合は、完了とせず、対象項目と理由を報告する
- 修正後に、375px相当の表示で対象ページと対象コンポーネントをすべて確認し、致命的・中の項目で主要操作と主要表示が欠けずに使えることを確認する
- 375px相当の表示を確認できない場合は、確認できなかったページ・項目と理由を明記して報告する。未確認の項目を「確認済み」として報告しない
- 広幅表示でも既存レイアウトが崩れていないことを確認する
- ローカルで `npm run build`（04_PORTAL）が成功してからプッシュする

## 未決事項（エージェントが勝手に決めない）
- 大会ドラフトモーダルの狭幅レイアウト方式（縦積み／折りたたみ／その他の方式）は監査では一意に決まっていない。既存UIに沿う最小変更を選び、選んだ方式と理由を報告すること。機能や操作手順の変更が必要になる場合は、実装前に報告する
- 勝率マトリクスで先頭列固定以外の方式（列構成の変更など）が必要になる場合は、実装前に報告すること
