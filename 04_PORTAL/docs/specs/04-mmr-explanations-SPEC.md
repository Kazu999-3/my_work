# SPEC：MMRまわりの説明の改善（KTMポータル）

対象：https://my-work-8jbd.vercel.app/balancer 、 /leaderboard 、 /history
Antigravityへの渡し方：このファイルをリポジトリに置き「このSPECを読んで実装して」と指示する。

## 1. 目的
「2つのランクが食い違って見える」「この数字は何基準か分からない」という混乱を、説明を常時見える場所に置くことでなくす。計算ロジックは変えない。

## 2. 現状の問題（2026-11-19 本番確認）
1. /balancer：同じ行に SoloQランク と KTMカスタムMMR のティアが並び、食い違って見える（例：SILVER／1373 GOLD、EMERALD／1512 PLATINUM）。どちらが何の基準か、常時分かる説明がない
2. /balancer：複数の初参加者が同じ代表MMR（1472、1352、1152など）を共有しているが、それが初期値・仮値である説明がない
3. /balancer 上部：「新規・ライト・復帰層10%」の内訳が 初参加0名・ライト1名・常連9名 で、10%が何の割合か読み取れない
4. /leaderboard：ロール別件数（TOP22・JG17・MID17・ADC23・SUP16＝延べ95件）と名簿92名が一致しない理由が不明。同じプレイヤーのMMRがレーンごとに異なり（例：TOP 1476 / MID 1640 / 代表 1533）、レーン別MMRであることが明記されていない
5. /history：デス0のKDA表示が通常式と合わない（例：10/0/3 → 15.60、7/0/8 → 18.00。(K+A)×1.2 相当）。デス0時の扱いの注記がない

## 3. やること
- [ ] 用語説明を常設する：/balancer と /leaderboard の上部に、折りたたみ式の説明ブロック（または「？」ではなく常時見える短い注記）で以下を明記する
  - SoloQランク＝Riot側のランク、KTMカスタムMMR＝KTM内の独自指標で、チーム分けに使うのはKTMカスタムMMRの方
  - MMRには「代表MMR」と「レーン別MMR」があり、/leaderboard はレーン別、/balancer は代表を表示している
  - 初参加者のMMRは初期値（仮値）で、試合を重ねると変動する
- [ ] 仮値の見分け：初期MMRのプレイヤーには「仮」バッジ等を付け、ツールチップでも理由が分かるようにする
- [ ] 経験層の割合表示：何を分母・分子にした割合か分かる文案にする（例：「参加10名中ライト層1名（10%）」）。内訳と一致しない表示は直す
- [ ] /leaderboard に注記を追加：件数はレーン別の延べ人数であること、名簿の実人数とは一致しないこと
- [ ] KDAの注記：まず実装コードでデス0時の計算式を確認し、その式に沿った注記を /history に追加する（例：「デス0の場合は ×1.2 で計算」※式はコードで確認した内容を書く。推測で書かない）。もしコード側の式が意図と違う疑いがあれば、注記は書かずに報告する

## 4. やらないこと
- MMR・KDAの計算ロジックの変更
- バランサーのアルゴリズムの変更
- ランキングの並び順や集計方法の変更

## 5. 完了条件
- [ ] 初見の人が /balancer を開いて、2つのランクの違いと仮値の意味が説明だけで分かる
- [ ] /leaderboard で「なぜ95件と92名が違うか」が注記で分かる
- [ ] 経験層の割合の内訳が文案から読み取れる
- [ ] /history にデス0時のKDAの扱いが、コードと一致する内容で注記されている（または不一致の疑いとして報告されている）

## 6. 未決事項（エージェントが勝手に決めない）
- KDAのデス0時ボーナス（×1.2相当）が仕様として意図したものかどうか
- 説明ブロックの置き場所とデザイン（候補を提示して確認を取る）
