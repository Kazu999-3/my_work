# 辞典・知識データの出典ルール

チャンピオン辞典（`champion_facts` / `champion_fact_claims` / `matchup_sentinel` の GLOBAL 行）や、それに準じる攻略知識を書き込む処理を作る・直す時は、次を守ってください。

## 1. 出典の無い自動生成で、既存の内容を上書きしない
- AI が生成した文章を辞典の列へ書く処理は「空欄を埋める」だけにする。既存の文章はライブラリ由来・人の編集の可能性があり、丸ごと置き換えると元に戻せない。
- 2026-10-07 実例: 毎週の自動更新（`champion_trend_worker.py`）が列を毎回上書きし、ライブラリ（動画・記事）承認で書き足された内容が84体・425項目で消えていた。検索の利用枠が無く、中身は「最新パッチは14.24」と答える約2年前の記憶だった。

## 2. 記述には出典を付けて `champion_fact_claims` に記録する
- 1件の記述ごとに `origin` と出典を持たせる（migration 89）。
  - `library` / `library_mixed`: ライブラリ記事の ID・URL・タイトルのいずれか（記事統合は `recordRevision` → `recordLibraryClaim` が自動で記録する）
  - `web_search`: 検索結果の URL 必須（Gemini の google_search グラウンディングの引用元）
  - `manual`: 管理画面で人が書いたもの
  - `ai_estimate`: 出典の無い AI 生成。画面では必ず「AI推定・出典なし」と表示する
- 出典の要件は DB の CHECK 制約でも保証している。制約を緩めて通すのではなく、出典を渡すように直すこと。
- 検索付きで呼んでも引用元が1件も返らなかった応答は、記憶ベースの回答と区別できないため保存しない。

## 3. 数値・固有名詞は特に慎重に
- 勝率・Tier・ビルド・ルーン・プロ選手の戦績・秒数などは、実データ（Riot API、OP.GG の収集データ）か検索の出典がある時だけ保存する。取れなければ null のままにし、それらしい値で埋めない（`known-regression-patterns` #5）。
- 画面に出す時は、根拠が実データ・出典付き・AI推定のどれかを利用者が見分けられるようにする。
