# 作業前の確認 (スマート確認 ＆ Vibe Coding 原則)

開発テンポ（Vibe）を最大化し、無駄な「y/n」往復を削減するため、操作のリスクレベルに応じて以下の基準を厳守してください。

## 1. 自律実行OK（確認不要・即座に実行して事後報告）
以下の非破壊操作は、ユーザーへの「y/n」確認を挟まず自律的に実行して構いません。
- **調査・読み取り**: `ls`, `cat`, `grep`, `git status`, `git diff`, 各種ログ調査
- **テスト・型チェック・ビルド**: `npm test`, `pytest`, `npx tsc --noEmit`, `npm run build`
- **非破壊スクリプト実行**: `--status`, `--scan-tags`, `--dry-run` などの読み取り・診断処理
- **新規ファイルの安全な作成**: 既存コードに影響を与えない設定ファイル・コマンド・スクリプトの新規配置
- **ピンポイントの軽微な修正**: 明白なタイポ・インポート漏れ・数行程度の限定的なバグ修正

## 2. 確認必須（必ず作業計画を報告し「y/n」を取ること）
以下の高リスク・破壊的操作を行う直前は、**必ず理由・対象・影響範囲を明示して「y/n」の承認を得てください**。
- **削除操作**: `rm`, `git rm`, テーブルやカラムの DROP、ファイルの物理削除
- **機密情報の変更**: `.env`, 本番APIキー, 秘密鍵の読み書き
- **広範囲の破壊的変更**: 複数ファイルを跨ぐ大規模な一括置換、既存アーキテクチャの大幅な書き換え
- **不可逆な実行**: 外部APIへの大量バッチ課金リクエスト、Git force push、本番DBの一括パッチ更新（`--apply`）
