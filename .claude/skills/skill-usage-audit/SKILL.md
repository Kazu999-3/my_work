# Skill Usage Audit

## 背景

スキルは作って終わりではなく、実際に使われているかを定期的に確認しないと際限なく増える。外部のnote記事複数本で「常設は5個以内が目安」「導入しても実運用は結局1桁個に収束する」という指摘が共通して見られた。このプロジェクトは既に20個以上のスキルを抱えているため、機械的に「呼ばれた形跡があるか」を可視化する。

## 使い方

```bash
python .claude/skills/skill-usage-audit/scripts/audit_skill_usage.py

# 一度も呼ばれていない/N日以上呼ばれていないものだけ強調したい場合
python .claude/skills/skill-usage-audit/scripts/audit_skill_usage.py --stale-days 14
```

リポジトリ内の全`SKILL.md`(node_modules等のサードパーティ配布物は除外)と、`~/.claude/projects/d--my-work/*.jsonl`に残っているセッショントランスクリプトを突き合わせ、スキルごとの呼び出し回数・最終使用日を一覧表示する。このスキル自身は何も削除・変更しない。

## 結果の読み方(重要な限界)

「呼び出し0件」は**「一度も役に立っていない証拠」ではない**。以下のケースを必ず踏まえること:

- 古いセッションのトランスクリプトはローテーション等で既にローカルから消えている場合がある(今回確認できた範囲は直近8セッション分のみ)。
- ユーザーの指示に基づいてスキルの中身を直接読んで参考にした/手作業で同等の手順を踏んだだけで、`Skill`ツール経由の正式な呼び出しとして記録されていないケースは検出できない。実際、このスキル自身のテスト実行時、今セッション中に作成・使用したはずの複数スキル(`known-regression-patterns`等)も0件と表示された。
- 作成直後でまだ使う機会が来ていないだけの新しいスキルも「0件」に含まれる。

**削除するかどうかは必ずユーザーに確認すること。** このスキルの役割は「棚卸しの材料を出すこと」までで、機械的な0件判定だけで自動的にスキルを削除する運用は行わない。

## 既知の落とし穴 (Known Pitfalls)

- **(2026-08-10)** Windowsコンソール(cp932)は絵文字(⚠️等)を直接printすると`UnicodeEncodeError`になる。スクリプト冒頭で`sys.stdout.reconfigure(encoding="utf-8")`が必須([[known-regression-patterns]]や`gemini-model-health-check`と同じ罠を本スキル自身が最初に踏んだ)。
- スキルは`.claude/skills/`直下だけでなく`04_PORTAL/.claude/skills/`のようにディレクトリスコープでも配置される。集計対象を単純に`.claude/skills/*/SKILL.md`だけに限定すると、そうしたディレクトリスコープ・スキル(例: `supabase-table-security`)への呼び出しが既知スキル一覧に存在せず表示から漏れる。`ROOT.rglob("SKILL.md")`でリポジトリ全体から拾い、`node_modules`等のサードパーティ配布物のみ除外する設計にすること。
