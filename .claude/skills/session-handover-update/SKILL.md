# Session Handover Update

## 背景

`CLAUDE.md`の§0により、次回セッション開始時は`HANDOVER_CLAUDE.md`と`02_FACTORY/TODO.md`が自動で読み込まれ、文脈復元に使われる。このセッションでの実装内容をここに書き残さないと、次回セッションはgit logやコード差分から手探りで文脈を再構築することになり非効率かつ不正確になる。

## 手順

### 1. 今日の日付で既存セクションが無いか確認する

```bash
python .claude/skills/session-handover-update/scripts/check_existing_section.py 2026-08-10
```

同日中に複数回このスキルを使う場合、新しい見出しを追加すると同じ日の記録が分散する。既存セクションが見つかった場合は、そのセクションの末尾に追記する（新規見出しを作らない）。

### 2. `HANDOVER_CLAUDE.md`への追記

`## 📜 2.x Claude Code期間 (開始日〜終了日)`という見出しの下に、機能領域ごとに`### 絵文字 (n) タイトル`のサブセクションを追加する形式を踏襲する（`HANDOVER_CLAUDE.md`内の直近のセクションを実例として参照）。

- 「〜の舞」「王国」等のポエミーな比喩表現は使わない（CLAUDE.md §3①のトーン規約）。
- 何を直したかだけでなく、**なぜ**（根本原因）を一言添える。次回セッションが同じ轍を踏まないための情報になる。
- 日付範囲は既存セクションの開始日を保ったまま終了日だけ今日に更新する（同一「期間」の継続の場合）。前回と大きく間が空いた場合や別ジャンルの作業なら新しいセクションを起こす。

### 3. `02_FACTORY/TODO.md`への追記

ファイル冒頭付近（最新の完了セクション群の先頭）に`## ✅ YYYY-MM-DD Claude Codeセッションで対応済み`の形式で新規セクションを追加し、箇条書きで対応項目を列挙する。既存の直近セクションの並び順（新しい日付が上）を崩さない。

未完了で持ち越すタスクがあれば、「## 🚧 技術的負債バックログ（継続追跡）」セクションに追記する（対応済みセクションに混ぜない）。

### 4. コミット前に確認を取る

ドキュメント更新もCLAUDE.md §3②の「作業前確認(y/n)」の対象。他のコード変更と一緒にコミットする場合は、通常のコミット確認フローに含めてよい。

## 既知の落とし穴 (Known Pitfalls)

- **(2026-08-10)** 同じ日に複数セッション（例: 朝と夜で別チャット）が走ると、日付だけを見出しキーにすると重複しやすい。`check_existing_section.py`は見出し行に日付文字列が含まれるかの単純一致なので、"2026-08-10"のような完全な日付が本文中に登場するだけでも拾ってしまう（誤検知はゼロ件側に倒さない設計）。見つかった場合は必ず実際の見出し行かどうか目視確認すること。
