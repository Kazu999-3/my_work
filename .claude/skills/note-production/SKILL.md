# 🚀 収益化note量産ワークフロー（500円モデル）

このワークフローは、Geminiの力を最大限に活用し、安定して読まれる「低単価note」を最速で作成・パッケージングするための手順です。

## 📋 事前準備
- [ ] 新規記事を書くか、過去記事のリライトかを決める（後述「0. 過去記事のリライト」参照）。
- [ ] `knowledge/reports/` 内の最新のトレンドレポート、または `knowledge/memo/` 内の特定のメモを一つ選ぶ。
- [ ] **テーマ選定基準**（2026-08-10、外部note記事群の分析より追記）: 複数候補から選ぶ場合は、①一次情報・実体験（他者にコピーされにくい独自の失敗談・検証結果があるか）②反復検索されるテーマか（パッチが変わっても繰り返し検索されうる普遍的な課題か、単発のトレンドだけで終わらないか）の2点を優先する。どちらも薄いテーマは、AIのまとめ記事と差別化できず検索・AI引用の両面で埋もれやすい。

### 0. （定期メンテナンス）過去記事のリライト（2026-08-10、外部note記事群の分析より追記）
新規記事の量産だけでなく、既存資産の棚卸しも収益化に効くという指摘があった。ユーザーから「過去記事を見直して」と依頼された場合、または新規ネタが薄い時期には、この手順を検討する。
1. `/admin/analytics`で閲覧数・スキが伸び悩んでいる、またはパッチが古くなった過去記事を選ぶ。
2. **冒頭だけを今の言葉で書き直す**（本文全体を作り直す必要はない）。古い前提（パッチ番号、メタ状況等）が残っていれば更新する。
3. 記事末尾に、関連する有料note・別記事への導線（CTA）が無ければ追加する。唐突な売り込みにならないよう、直前に「気づきのギブ」を挟んでからリンクを置く（`30_content_factory.md`のCTA Bridgeルールに従う）。
4. 新規執筆と違いStep 1〜3.5のフルパイプラインは不要。該当ファイルと`note_articles`テーブルの該当レコードを直接更新すればよい。

## 🛠️ ステップ詳細

### 1. 超・ディープリサーチ (Protocol v3)
1. **多角的データ収集**: `.agent/rules/31_deep_research_v3.md` に基づき、ターゲットとするテーマを 5 方向から徹底調査。
2. **リサーチ報告書 (Artifact) の作成**: 執筆前に、具体的な数値、クロスリファレンス、独自推論をまとめた報告書を作成し、品質の「核」を確定させる。
3. **承認**: 調査結果の密度に納得してから Step 2 へ移行する。

### 2. 構成案とフック設計
1. リサーチ結果を元に、`.agent/rules/30_content_factory.md` の 8 モジュールを含んだ詳細構成を作成。
2. 読者の感情を動かすフック（驚き・共感・好奇心）をタイトルと導入に設計する。

### 3. 本文の「極限」執筆 (Worker)
1. **最低 8,000〜10,000 文字以上**を目指し、各セクションの密度（具体的対面、秒単位の解説、失敗談）を高める。
2. `note-article-drafter` スキルを使用し、デザインされた無料・有料の断絶を作る。
3. 生成されたドラフトに対し、`style-auditor` スキルを適用して AI 特有の語彙や曖昧な断定をすべて切除する。

### 3.5. レビュー＆改善ループ (Reviewer, 2026-08-03追加)
参考: Loop Engineering（Worker/Reviewerを分離し、明確なpass/fail基準と反復上限を設ける設計）。
コスト（Gemini呼び出し回数）を抑えるため、**無制限の反復ではなく最大2回まで**とする。

1. Step 3 で作った本文に `article-review` スキルを適用し、6観点でpass/fail判定と改善版(v2)を得る。
2. **fail**の場合、article-reviewの指摘を反映したv2を採用し、もう一度article-reviewを適用する(2回目)。
3. 2回目もfailなら、そこで打ち切る（無限ループ禁止）。最新版をそのまま採用し、残っている指摘事項を人間向けの申し送りとして明記する。
4. **どちらにせよ、noteへの実際の公開は本ワークフローの範囲外・人間の承認制のまま**（`/admin/analytics`で「公開済みにする」操作をするまで下書きのまま）。このループが自動化するのは下書きの品質改善だけで、外部への公開アクションは自動化しない。

### 4. プロモーション・パッケージング
1. note の表示最適化を考慮したタイトル（32文字以内）の磨き込み。
2. **連載型 X スレッド (4〜6連投)** を生成し、記事の一部を有益情報としてギブするプロモーション体制を構築。
3. アイキャッチ画像生成ツールを用い、記事の価値を象徴するプレミアムなアイキャッチを生成。

## 🎯 期待される成果
- 読者が「500円でも安すぎる」と感じる、圧倒的情報密度の実用コンテンツ。
- 公開初日から X での拡散と購入を同時に狙える、宣伝素材を含めたパッケージ。

---
> [!IMPORTANT]
> 「量より質、そして質の圧倒的な量（文字数と密度）」が収益化モデルの基盤です。リサーチの妥協は記事の死を意味すると心得よ。
