# Handover Staleness Check

## 背景

`session-handover-update`スキルは「使うことを覚えていれば」機能するが、実際に使ったかどうかを確認する手段が無かった。日付文字列の一致で判定しようとすると、同日中に複数セッションが走った場合に「まだ今日の日付だから大丈夫」と誤判定してしまう(実際に最初のバージョンでこの誤検知が起きた)。そのため、日付ではなく**HANDOVER_CLAUDE.md/TODO.mdを最後に更新したコミットより後に、どれだけのコミットが積まれているか**をgitの祖先関係で判定する。

## 使い方

```bash
python .claude/skills/handover-staleness-check/scripts/check_staleness.py
```

このスキル自体はファイルを一切書き換えない。未反映の可能性があるコミット一覧を表示するだけなので、実際に反映するかどうかは`session-handover-update`スキルの手順に従うこと。

## 結果の読み方

- **✅ 反映済み**: 両ファイルとも直近のコミットで更新されている。何もしなくてよい。
- **未反映コミットが少数(閾値未満)**: 些細な変更(コメント修正等)である可能性が高い。次回セッション終わりにまとめて反映すれば十分で、今すぐ`session-handover-update`を走らせる必要はない。
- **⚠️ 未反映コミットが閾値超え**: 実質的な機能追加・バグ修正が複数積まれているのに記録が追いついていない可能性が高い。表示されたコミット一覧を見て、`session-handover-update`スキルで反映するかユーザーに確認する。

## 既知の落とし穴 (Known Pitfalls)

- **(2026-08-10)** 初版は「ファイル内の最新日付文字列」と「その日付以降のコミット数」を比較していたが、同じ日に複数セッションが走ると更新した直後でも「今日のコミットが多数ある」と誤検知した。**コミットの祖先関係(`git log <baseline>..HEAD`)による比較に変更して解消**。日付ベースの比較に戻さないこと。
- `.wrangler`等のビルド成果物ディレクトリはHANDOVER更新の対象外だが、このスキルの監視対象パス(`02_FACTORY`/`03_SYSTEMS`/`04_PORTAL`/`.claude`)には`03_SYSTEMS/ktm_bot/.wrangler`も含まれてしまう。ビルド成果物だけの変更が誤って「未反映コミット」に数えられていないか、一覧を目視で確認すること。
