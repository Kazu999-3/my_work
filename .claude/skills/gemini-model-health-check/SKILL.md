# Gemini Model Health Check

## 背景（なぜこのスキルが必要か）

2026-08-08に、当時「架空のモデル名エラー」と誤診断されたバグの「修正」が、実際にクォータのあった`gemini-3.x`系モデルを、AI Studio上で無料枠が0/0(そもそも割り当てなし)だった`gemini-2.0-flash`/`gemini-1.5-flash`系へ後退させていた。この状態は「モデル名として実在する」ため`ListModels`API等では正常に見え、コードレビューだけでは気づけない。実際に生成リクエストを送って429/RESOURCE_EXHAUSTEDが返るかどうかでしか判別できない。

**教訓**: Geminiモデル名に関するバグ調査・変更の際は、「このモデル名は正しいコードか」ではなく「このアカウントで今すぐ本当に呼び出せるか」を必ず実測すること。

## 使い方

```bash
python .claude/skills/gemini-model-health-check/scripts/check_gemini_models.py
```

このスクリプトは:
1. `03_SYSTEMS/`・`04_PORTAL/src/`配下の`.py`/`.ts`/`.tsx`/`.js`から`gemini-*`形式の文字列を自動収集する（embedding/robotics/tts系等の通常のテキスト生成テストでは検証しづらいモデルは除外）。
2. 収集した各モデル名に対し、`.env`の`GEMINI_API_KEY_FREE`（無ければ`GEMINI_API_KEY`）を使って実際に軽量リクエストを送る。
3. 結果を「✅動作OK」「❌クォータ割り当て0(このアカウントでは使用不可)」「⚠️429(枯渇中、一時的な可能性)」等に分類し、どのファイルがそのモデルを参照しているかも一覧表示する。

分単位レート制限を無駄に消費しないよう、モデルごとに1秒間隔を空けて実行する。

## 結果の読み方（誤検知に注意）

このスクリプトは単純な文字列検索であり、実際に`model=`として呼び出しているコードと、「なぜこのモデルを使わないか」を説明したコメント中の言及（例: `// gemini-2.5-flash-liteは404だったのでgemini-3.5-flash-liteに変更`）を区別できない。**「⚠️ 以下のモデルは現在使用できません」に出てきたファイルは、そのファイルの該当行を実際に開いて、コメントの中だけの言及か、本当に`model_id=`/`model:`として渡されているコードかを目視で確認すること。** 動作確認済みモデルへの置き換え作業をした直後は、経緯を説明するコメントに古いモデル名が残るため、この一覧に再度出てくるのが正常。

- **❌ クォータ割り当て0**: エラーメッセージに`limit: 0`が含まれる場合。これは「今日の分を使い切った」ではなく、そもそもこのアカウント・プロジェクトにこのモデルへの無料枠が存在しないことを意味する。待っても直らない。**該当ファイルを`gemini-3.1-flash-lite`（2026-08-10時点で15RPM/500RPDの実クォータを確認済み、`ai_helper.py`のデフォルトフォールバックと同じ）へ変更することを検討する。**
- **⚠️ 429(枯渇中)**: `limit: 0`を含まない429。日次/分単位の実使用量による一時的な枯渇の可能性があるため、時間を空けて再実行して切り分ける。
- 実行前に、Google AI Studio(https://ai.dev/rate-limit)のクォータ画面を確認できるなら、そちらの数値（RPM/TPM/RPD）と突き合わせるとより確実。

## 既知の落とし穴 (Known Pitfalls)

- **(2026-08-10)** `.env`の`GEMINI_API_KEY_FREE`と`GEMINI_API_KEY`が同一の値であることが判明済み（このプロジェクトでは「キーを分けてクォータを分離する」設計は現状機能していない）。将来的に本当に別キーを用意した場合は、このスクリプトを両方のキーで実行して結果が変わらないか確認すること。
