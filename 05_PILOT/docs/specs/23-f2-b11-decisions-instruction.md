## 決定2（B-11）：単件承認の確認は「③＋①」の組み合わせで入れる

### やること
- [ ] **③ 複数チャンピオン記事の承認に確認を出す**：`approveOne` の対象が、確認なしで自動分解＆複数教本へ直接統合される経路（報告の条件：`!isPreviewing && item.isMultiChampion && !item.is_atomic` で `action: 'decompose_auto'` が走るケース）に当たる場合のみ、実行前に確認を出す。確認文面には「複数チャンピオンの教本へ自動で分解・統合される」旨と対象記事が分かる情報を含めること。
- [ ] **① キーボード `A` 経由の承認に確認を出す**：`handleKeyDown` から `approveOne` が呼ばれる場合は、実行前に確認を出す。ボタン（クリック）経由の通常の単件承認は、従来どおり確認なしの即時承認のままにする。
- [ ] ③と①の両方に当たる場合（キーボード `A` で複数チャンピオン記事を承認）も、確認は1回だけ出す。
- [ ] 確認の出し方は、review 画面の既存の確認（一括承認など）の方式・文面の様式にそろえる。

### やらないこと
- 通常の単件記事のボタン経由の承認への確認追加（即時承認を維持するのが決定）。
- 一括承認・却下など、既に確認がある操作の変更。
- 代替案②（Undo・送信遅延）や④（Aキーの無効化・変更）の実施。
