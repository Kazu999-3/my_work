# SPEC 13: Ollama と Gemini の生成品質・量の比較検証

作成: 2026-11-20（Muse）
対象: 05_PILOT/src/lib/knowledgeDecompose.ts（知見分解）/ scripts/llm_fallback_adapter.py（事実抽出）

## 目的

Ollama（qwen2.5:7b）を使うことで生成物の質・量が Gemini と比べて下がるのかを、同条件の実測で明らかにし、Ollama の担当範囲をユーザーが判断できる材料を出す。

## 背景

- ユーザーの関心は API の上限ではなく生成物の質と量。「下がるなら Ollama は使わない」が前提の方針。
- 現状の実測は「実動画1本を Ollama で処理できた（13件抽出・29秒）」までで、Gemini と同条件で比べたことはない。
- 現在の担当分担: 最終生成（記事化）は Gemini。Ollama は前段の事実抽出と Gemini 障害時のフォールバック、およびローカル実行時の知見分解（本番 Vercel からは到達できないため、本番では常に Gemini）。

## やること

- [ ] 比較用スクリプトを用意し、同一入力を Ollama と Gemini の両方で処理する（本番のルーティング設定は変更しない）
- [ ] 対象A: 知見分解（knowledgeDecompose）。既存の記事3本で比較する（短め1本・長め1本・複数チャンピオン混在1本）
- [ ] 対象B: 事実抽出（llm_fallback_adapter）。既存の動画字幕3本で比較する（短尺・中尺・長尺）
- [ ] 比較項目: 抽出件数 / JSON形式の成功率（パース可否）/ 文字化け・形式崩れの件数 / Gemini にあって Ollama にない知見の差分リスト / 処理時間
- [ ] 両エンジンの生出力をファイルに保存し、レポートから参照できるようにする
- [ ] レポートを 05_PILOT/docs/specs/reports/ に置く（サンプルごとの比較表＋総評: どの処理なら Ollama で代替できそうか、できないか）

## 注意（Gemini 無料枠）

- Gemini 側の実行は無料枠の1日上限に触れるため、サンプルは上記の本数に絞り、追加実行しない。429 が出たら中断し、その旨を報告する（無理に進めない）

## やらないこと

- 結果に基づく担当範囲・ルーティングの変更（判断はユーザー）
- 本番の環境変数・設定の変更
- Ollama モデルの変更や追加モデルの試行（気づきがあれば「提案」として報告に分けて書く）

## 未決事項（勝手に決めない）

- Ollama の担当範囲の最終判断
- モデルサイズを上げる（例: 14B）などの対案の実施可否

## 完了条件

- 比較レポートと生出力が揃い、ユーザーが「Ollama をどこまで使うか」を判断できること
- 本番の動作に影響する変更が含まれていないこと
