# SPEC 19: 致命的欠陥とデータ保護まわりの修正

作成: 2026-11-22（Muse）
対象: 05_PILOT
根拠: 2026-11-22 の全量コード監査（致命的2件ほか）と同日の本番ブラウザ監査。監査報告書の項目番号（F-1、A-1 など）を併記する。

## 目的
画面遷移時のクラッシュ可能性と、「読み込み失敗に気づかず既存データを上書き・削除してしまう」事故の芽を先に潰す。あわせて、副作用の大きい操作への確認ステップを既存の様式にそろえる。

## やること
- [ ] 1. **GlobalNavbar の Hooks ルール違反の修正**（F-1、`src/components/GlobalNavbar.tsx:40-54`）。`/overlay`・`/login` 判定の早期 return より後に useState/useRef/useEffect が呼ばれている。フックをすべて早期 return の前に移し、遷移時にフック数が変わらないようにする。
- [ ] 2. **dict-maintenance のロード失敗対策**（A-1、`app/admin/dict-maintenance/page.tsx:66-112`）。
  - 読み込み中は読み込み中であることを画面に表示する（現状 `loading` state が未使用）。
  - ロード失敗時はエラーを画面に表示し、再試行できるようにする（現状は console.error のみで無言）。
  - **ロードが成功していない状態では保存できないようにする**（空フォームのまま保存して既存の教本を上書きする事故を防ぐ）。
- [ ] 3. **dict-maintenance の未保存ガード**（B-17）。編集中に別チャンピオンを選ぶ・画面を離れるとき、未保存の変更があれば確認する（dirty チェック）。警告なく入力が破棄される状態をなくす。
- [ ] 4. **副作用の大きい操作への確認ステップ追加**。文面は QueueTab の既存様式（対象・件数・副作用を明記）にそろえること。
  - dashboard の「失敗タスクを再実行（N件）」（B-12、`app/admin/dashboard/page.tsx:177,322`）
  - WorkerStatusPanel の「失敗タスク一括再試行」「辞典合成を起動」「新着巡回を起動」（B-13、`app/admin/youtube/WorkerStatusPanel.tsx:69-115,244-285`）
  - dict-health の「確認済みにする／取消／AI再リサーチ起票」（B-14、`app/admin/dict-health/page.tsx:240-246,555-583`）
- [ ] 5. **KnowledgeIngestModal のキュークローズ（削除）の成否確認**（B-15、`components/KnowledgeIngestModal.tsx:213-218`）。確認ステップを追加し、`res.ok` を確認して失敗時は画面上の項目を復旧し、失敗したことを表示する（現状は楽観的削除で失敗しても画面からだけ消える）。
- [ ] 6. **最適化反映モーダルの最終確認**（B-16）。`ChampionOptimizeModal.tsx:51-72,191-205` の「反映する」に最終確認を追加する。`LaneGuideOptimizeModal.tsx:50-72,76-84` には最終確認に加えて「現在の本文は上書きされ戻せない」旨の警告文をモーダル内に出す。
- [ ] 7. **DecomposeModal の説明矛盾の解消**（C-19、`app/admin/review/_review/DecomposeModal.tsx:118 vs :200`、`app/admin/review/page.tsx:520`）。ヘッダー等は「各教本へ直接統合」、操作バーは「未承認知見として登録」と正反対の説明が同居している。実装の実際の挙動をコードで確認し、説明文を実挙動に合わせて統一する。どちらの説明が正しかったかを報告すること。
