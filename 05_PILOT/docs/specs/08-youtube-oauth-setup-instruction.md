# 指示文：YouTube OAuth認証情報の設定（SPEC 08 自動クローズの前提作業）

## 目的
- プレイリスト追加に必要な YouTube OAuth 認証情報が未設定で、自動退避＆クローズが止まっている。初回のみのセットアップとして、リフレッシュトークンを取得し、必要な場所へ設定する。

## 現状（コードで確認済み）
- 認証情報は環境変数 `YOUTUBE_OAUTH_CLIENT_ID` / `YOUTUBE_OAUTH_CLIENT_SECRET` / `YOUTUBE_OAUTH_REFRESH_TOKEN` の3つ。
- 使う場所は2か所（どちらも同じ変数名・同じ値でよい）：
  1. ローカルの自動クローズ（scripts/auto_close_terminal_errors.py が自分の環境変数から直接読む）← 自動クローズの復旧に必須。
  2. Pilot 本番（05_PILOT/src/app/api/youtube/playlist/add/route.ts と queue/route.ts の close_to_playlist が Vercel の環境変数を読む）← 画面からのプレイリスト追加にも必要。
- 追加先プレイリストは既定の PLPiEXmmDzgcs（手動確認用）。同意は、このプレイリストを編集できる YouTube チャンネルの Google アカウントで行うこと。別のアカウントで同意すると追加が失敗する。

## 手順
1. **OAuthクライアントの用意**：末吉が YouTube Data API 用に使っている Google Cloud プロジェクトがあればそれを使う。OAuth クライアント（クライアントID/シークレット）が無ければ新規作成する（種類は「デスクトップアプリ」がローカル取得に向く）。
2. **同意画面のステータス確認**：OAuth 同意画面が「テスト」モードのままだとリフレッシュトークンが7日で失効する。「本番環境」に公開しておくこと（未確認アプリの警告画面が出るのは想定内。末吉が「詳細→続行」で進む）。
3. **リフレッシュトークンの取得**（ローカルで実行）：
   - 認可URLを組み立てて末吉のブラウザで開く：scope は `https://www.googleapis.com/auth/youtube`、`access_type=offline`、`prompt=consent` を必ず付け、redirect_uri はローカルループバック（http://localhost:<ポート>）。
   - 末吉が対象の Google アカウントで同意する。戻ってきた code をトークンエンドポイントで交換し、refresh_token を得る。
   - refresh_token はローカルコンソールでの表示まで。**Git・DAILY_LOG・チャット・リポジトリ内ファイルに絶対に書かない**。
4. **ローカルへの設定**：常駐ワーカーが読む .env に3変数を設定する。先に .env が .gitignore 済みであることを必ず確認する（されていなければ設定前に末吉へ報告）。
5. **Vercelへの設定**：3変数の値を末吉が Vercel（ktm-pilot プロジェクト → Settings → Environment Variables、Production）へ直接入力する。Antigravity は値を受け取らない・転記しない。設定後に本番の再デプロイが必要（環境変数は再デプロイで反映される）。
6. **検証して報告する**：
   - 自動クローズを1サイクル実行し、needsAuth（401）が出ないこと、対象（2026-11-20時点で114件）がプレイリストへ追加され manually_closed へ遷移すること。件数の前後（エラー件数・クローズ済み件数）を報告する。
   - 追加に失敗する件があれば、理由（アカウント権限・プレイリスト側の問題など）を切り分けて報告する。

## やらないこと
- トークン類の値をコミット、ログ、チャットへ残すこと（万一コミットした場合は漏洩扱いとして即報告し、再発行する）。
- 自動クローズの仕組み・対象・フェイルセーフ規則の変更。
- プレイリスト自体の作成・変更。

## 完了条件
- ローカル自動クローズが認証エラーなく動き、滞留している終端エラーがクローズへ遷移する。
- Vercel 側にも同じ3変数が設定され、再デプロイ済みである（末吉の画面で確認）。
