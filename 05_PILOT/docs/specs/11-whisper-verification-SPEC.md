# SPEC 11: Whisper文字起こしの実働検証と改善

作成: 2026-11-20（Muse）
対象: scripts/youtube_worker.py / scripts/whisper_transcriber.py

## 前提の訂正

当初「字幕なし動画の救済に Whisper を導入する」SPEC の想定だったが、コードを確認したところ **Whisper は実装済みで既定ON** だった（`ENABLE_WHISPER` 既定1、モデル base、対象は20分以下、`whisper_transcriber.py` あり。フォールバック順は 字幕 → Whisper → Gemini映像解析）。したがって本SPECは導入ではなく「本番で実際に機能しているかの検証と、失敗の切り分け・改善」とする。

## 現状の問題

- 実装はあるのに、本番の常駐ワーカー環境で Whisper 経由で救済された本数・失敗理由が未確認。
- `error_no_transcript` の終端エラーは今も発生しており、自動クローズ（SPEC 08）の対象にも混ざっている。Whisper 対象（20分以下）だったのに救えなかった動画があるのか、あるなら理由は何かが分かっていない。

## やること

- [ ] 実機検証: 字幕なし動画を1本選び、常駐ワーカーと同じ環境で処理し、ログの経路（🎙️ Whisper開始 → ✅ 文字取得、または ⚠️ 失敗理由）を確認する。whisper パッケージの有無、モデル（base）のダウンロード可否も含める
- [ ] 失敗の分類: 直近の `error_no_transcript` 終端エラー動画について、Whisper 対象だったか（長さ20分以下か）と、失敗理由を分類して件数を出す（例: パッケージ未導入 / モデル取得失敗 / 文字起こし結果が最低文字数未満 / 長さ超過で映像解析へ回ったが映像解析も失敗 / その他）
- [ ] 見える化の改善: Whisper の成否と失敗理由が後から追えるよう、既存のログ・キュー記録の範囲で小さく改善する（大規模な作り替えはしない）
- [ ] 報告: 検証した動画ID・結果・分類件数を明記する

## やらないこと

- パイプライン全体の作り替え
- 既定値（WHISPER_MODEL、WHISPER_MAX_SEC、WHISPER_MIN_CHARS）の無断変更。変更が有効そうな場合は、数値根拠つきの「提案」として報告に分けて書く

## 未決事項（勝手に決めない）

- モデルを base から上げるか（精度と処理時間のトレードオフ）
- 対象の長さ上限（現在20分）を広げるか
- 上記は計測結果を見てユーザーが判断する

## 完了条件

- 実機検証の結果と失敗分類が報告され、Whisper が本番で機能しているかどうかが断定できること
- コードを変更した場合は、既存の字幕 → Whisper → 映像解析の順序と、Gemini 429 がリトライを消費しない既存仕様を壊していないこと
