# SPEC 10: コーチページの内容品質（生成文のノイズ除去・数値の固定・汎用文のレーン適合）

## 目的
- SPEC 07で画面と自由質問が入ったが、内容の信頼性に問題が残っている。末吉のメイン対面（Zyra vs Vi、JG）での実測をもとに、コーチの出力を「そのまま実戦で使える」品質に近づける。

## 現状の問題（2026-11-20 本番実測、Zyra vs Vi・JG）
1. **クリア基準秒数が描画ごとに変わる**：敵クリア基準が 2:44 → 2:42 と再表示で変動した。取得元は Supabase `champion_jungle_timing_agg.external_fastest_clear_sec`（/api/lol/matchup-blueprint の fetchClearTimes）。取得クエリに並び指定がなく、同チャンプに複数行あると返る行が不定になる疑いがある（要特定）。
2. **生成文にノイズが残る**：
   - 自由質問の回答に未記入プレースホルダー「約何秒」がそのまま表示された。
   - スキル名の文字化け「Q（突っ向勝負）」（ViのQは Vault Breaker）。弱みメモにも「通常攻撃の信長値が低い」という意味不明な語がある。
   - 弱みメモの文章が「また、」で始まり、冒頭が欠けた断片になっている。
   - 回答内でRの話とQの話が混線するなど、論理の検証がされていない。
3. **汎用手順書がレーン不適合のまま**：対面専用データがない場合の3段階手順書（BLUEPRINTS未登録時の共通文）は、JG対面でも「ウェーブ管理」などレーン用語が混ざる。専用データがあるのは数体のみ。
4. **自由質問の回答が遅い**：1回の質問に約1〜2分かかった（試合前に使うには長い）。

## やること
- [ ] **クリア秒数の決定性を直す**：変動の原因を特定して報告したうえで、同チャンプでは表示値が描画ごとに変わらないようにする（取得行の決定、集計側の重複解消など、原因に即した方法で）。実データがない場合は推測値を出さず「データなし」と分かる表示にする。
- [ ] **自由質問の回答を出す前に検証する**：「約何秒」「○○」「XX」等の未記入パターンが残っていたら、そのまま表示せず再生成するか該当箇所を落とす。スキル名は正本データ（Riot公式のチャンピオン/スキル名）と照合し、一致しない表記は修正または除去する。
- [ ] **弱みメモ等の表示文面を整える**：「また、」で始まるような断片化した文は表示時に冒頭を整えるか、断片と分かるデータは表示対象から外す。文字化け・意味不明な語を含む辞典データは、検出して件数と該当チャンプを報告する（辞典データ全体の書き換えはこのSPECではしない）。
- [ ] **汎用手順書をレーン適合させる**：対面専用データがない場合の共通手順書を、レーン別（少なくともJG用はレーン用語を混ぜない）に用意する。あわせて、専用データがない対面では汎用手順書の見せ方を弱め（「一般的な流れ」表示は維持）、対面固有の具体策が出る自由質問への誘導を強める。
- [ ] **回答速度の調査**：自由質問に60秒超かかる原因（辞典照合・生成のどこか）を特定して報告し、短縮案を提示する。モデルの変更など仕様に関わる対策は、報告後に末吉が判断する。

## やらないこと
- 辞典データ全体の作り直し・大量書き換え（検出と報告まで）。
- 対面専用手順書（BLUEPRINTS）の手書き追加（データ拡充は既存の解析パイプライン側の話）。
- コーチ画面のレイアウト変更（SPEC 07の範囲で確定済み）。

## 完了条件
- Zyra vs Vi（JG）で、クリア基準秒数が再表示しても変わらない。
- 自由質問の回答に未記入プレースホルダーや文字化けしたスキル名が残らない（同対面で再質問して確認）。
- JG対面の汎用手順書にレーン用語（ウェーブ等）が混ざらない。
- 変動原因・ノイズ検出件数・速度の原因が報告されている。

## 未決事項（エージェントが勝手に決めない）
- 回答検証で再生成を使う場合の追加APIコスト（回数上限など）。まず検証の仕組みを報告し、コストが増える場合は末吉の判断を仰ぐ。
- 回答速度の短縮策の選択（モデル変更を含む場合は特に）。
- 断片化・文字化けした辞典データの扱い（除去か、再生成か）は、検出レポートを見て末吉が決める。
